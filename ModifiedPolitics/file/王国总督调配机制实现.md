# 王国总督调配机制实现

## 配置

配置文件：`ModifiedPolitics/ModuleData/culture_governor_policies.xml`

该文件同时在模块根目录的 `SubModule.xml` 中注册，仅对战役相关游戏类型加载。启动战役时，`Main.OnGameStart()` 按 Bannerlord 标准流程注册 `CultureGovernorPolicy` 类型，再由 `MBObjectManager.LoadXML()` 创建对象；每个对象在 `Deserialize()` 中解析文化引用与开关并注册到查询管理器。

- `empire`、`aserai` 默认启用王国统一调配。
- 未配置或配置为 `false` 的文化保留原版氏族总督机制。
- 配置以 `Kingdom.Culture.StringId` 为键，不在代码中写死文化名单。

## 执行时机

- 新游戏创建后执行一次。
- 此后每周执行一次。
- 王国为空、已灭亡或文化为空时不处理。

## 分配规则

1. 启用王国统一调配的王国会跳过原版 `UpdateGovernorsOfClan()`。
2. 每轮先清理已经离开领地所属王国的跨氏族总督。
3. 只处理没有总督、也没有总督正在赴任的城镇与城堡，不替换现任总督。
4. 聚合王国内非雇佣兵、非玩家氏族的合格英雄。
5. 领地按“城镇/城堡基础值 + 繁荣度平方根 + 绑定村庄数”排序。
6. 英雄按 Steward、Trade、Leadership、Charm、Engineering、Tactics 和正荣誉加分计算；同文化乘以 1.2。
7. 使用贪心分配，一个英雄每轮最多获得一个职位。

## 互斥与边界

- 死亡、未激活、被俘、已有部队、已有总督职位或正在旅行的英雄不参与候选。
- 使用游戏自身 `CanHeroBeGovernor()` 作最终资格校验。
- 现任总督在 AI 领军评分中直接获得最低值；即使其他路径尝试创建领主部队，也会被防御性拦截。
- 玩家氏族英雄不进入 AI 自动候选池，但玩家作为启用该制度的王国君主时，王国统一调配仍照常管理其他氏族英雄。
- 玩家不是国王时仍可通过原版界面手动任命自己领地的总督；本模组只拦截原版 AI 自动分配，不拦截玩家任命操作，也不会替换现任总督。

## 诊断日志

- Notice：王国统一调配成功任命总督。
- Notice：跨氏族总督离开领地所属王国后被解除职务。
- Debug：空缺领地没有任何合格候选人。
- 所有新增日志使用本地化文本，简体中文位于 `modifiedpolitics-zho-CN.xml`。
- 上述运行日志仅针对玩家当前所在王国输出；玩家没有加入王国时不输出。

## Kingdom/Fiefs 界面

- 详情页原有的领主头像被总督卡片替换，显示当前总督的头像和姓名；空缺时显示“无总督”。
- 所有玩家都可以查看总督信息和总督效果提示。
- 只有玩家是当前王国统治者且该文化启用了王国统一调配时，才可以点击卡片进行任命或撤销。
- 候选面板复用原版 Clan/Fiefs 的大型卡片弹窗，显示头像、管理技能、赴任时间、总督效果和总督技能。
- 玩家手动任命时可以选择当前王国所有正常、非雇佣兵 Clan 的合格英雄，包括玩家 Clan 英雄。
- 任命提交时会再次校验王国、统治者身份与英雄状态，避免弹窗打开后状态变化造成无效任命。
