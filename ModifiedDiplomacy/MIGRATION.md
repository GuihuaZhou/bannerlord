# ModifiedDiplomacy 迁移与重构计划

## 目标

`ModifiedDiplomacy` 最终独立负责全部王国外交功能。`ModifiedPolitics` 只保留内政、王国政治、战争潜力和战争倾向的数据来源，不再直接实现外交按钮、决议、条约和组合谈判。

迁移采用逐批切换：每一批先在新 Mod 建立新实现，再停用 `ModifiedPolitics` 中同一功能的注册入口。任何时刻只能有一个 Mod 注册同一补丁、行为或 UI 扩展。

## 迁移期间的依赖方向

第一阶段采用临时依赖：

```text
ModifiedDiplomacy -> ModifiedPolitics -> ModifiedArmy
```

这样可继续使用已经验证过的旧功能，并逐项迁移。不得让 `ModifiedPolitics` 反向引用 `ModifiedDiplomacy`，否则会形成循环依赖。

最终目标：

```text
ModifiedDiplomacy -> ModifiedArmy
ModifiedPolitics  -> ModifiedArmy
```

如果外交评分仍需战争潜力或战争倾向，应先把这两项整理成只读接口或独立的共享程序集，再移除临时依赖。外交层不得直接读取政治模块的内部 Manager。

## 功能边界

### ModifiedDiplomacy

- 统一外交查询、评分、合法性检查与执行 API。
- 宣战、和平、同盟、贸易协定。
- 建立和解除附庸、傀儡关系，以及独立。
- 王国决议和玩家确认流程。
- 组合外交提案、条款、投票、执行与恢复。
- 外交 AI，包括主动提案与回应提案。
- 王国外交界面的关系展示、操作按钮和组合谈判界面。
- 外交存档数据、冷却时间、条约记录和日志。

### ModifiedPolitics

- 战争潜力。
- 战争倾向及其事件来源。
- 王国内政、家族政治和其他非外交功能。
- 在迁移结束前，临时保留尚未转移的旧外交实现。

## 分批迁移顺序

### 第 0 批：空壳与边界

- 建立可独立编译、加载的 `ModifiedDiplomacy`。
- 不注册 CampaignBehavior，不复制 Harmony 补丁，不加载外交 UI。
- 记录类的归属和迁移状态。

验收标准：同时启用两个 Mod 时，游戏行为与只启用当前 `ModifiedPolitics` 一致。

当前状态：已完成。

首个无存档迁移批次同时完成：

- 王国统治者在人物谈判中交易封地的补丁。
- 宗藩同盟限制的最终执行补丁。
- 宗藩贸易限制的查询与最终执行补丁。
- 加载存档、宣战后清理非法同盟和贸易协定的行为。

这些类型已经从 `ModifiedPolitics` 删除，并只在
`ModifiedDiplomacy` 注册。规则服务和宗藩存档仍由旧模块临时提供。

第二个无存档迁移批次：等待编译和游戏验证。

- 傀儡战争与和平同步行为。
- 附庸战争义务同步行为。
- AI 宗藩提案、解除关系和独立提案行为。
- AI 组合外交提案行为。
- 流亡家族投奔新王国的模型、行为和家族存续补丁。

这些行为的注册入口已经转移到 `ModifiedDiplomacy.Main`。现有评分、
决议、同步服务和存档数据仍由 `ModifiedPolitics` 提供，因此本批只改变
代码归属，不改变存档类型或外交计算结果。

### 第 1 批：统一外交领域模型

- 建立 `DiplomacyActionType`、`DiplomacyTerm`、`DiplomacyProposal`。
- 建立统一结果类型：合法性、评分明细、拒绝原因、执行结果。
- 将双边协议和单边行动明确分开。
- 为旧实现建立只读适配器，不改变当前游戏行为。

验收标准：新 API 能给出与当前单项外交相同的可用性和评分结果，但仍由旧代码执行。

### 第 2 批：评分与规则

- 统一宣战、和平、同盟、贸易、宗藩关系的合法性检查。
- 把战争潜力和战争倾向作为明确的评分输入，而不是散落的补丁。
- 修正最终规则：附庸国和傀儡国都不能签订同盟。
- 区分提出方支持、目标方接受、本国投票三种判断。

验收标准：单项按钮、AI判断和组合条款引用同一评分入口，不再各算一套。

### 第 3 批：执行器与存档

- 迁移宗藩状态、条约和冷却数据。
- 建立幂等执行器和完整预检。
- 执行前冻结提案快照；执行失败时记录已执行步骤并安全重试。
- 迁移旧存档时兼容原有字段，不改变 Saveable 类型标识。

验收标准：保存、加载、执行、重试不会产生重复条约或重复扣款。

### 第 4 批：王国决议与提案流程

- 迁移单项外交决议。
- 迁移组合外交决议。
- 统一玩家发起、AI发起、AI向玩家提案和玩家确认。
- 单边行动只进入本国决议；双边协议先判断对方接受，再进入本国决议。

验收标准：所有入口都遵循同一生命周期，不能绕过目标国判断或本国投票。

### 第 5 批：组合谈判 UI

- 迁移谈判 VM、ScreenService、Prefab 和 UIExtender。
- 继续保留 Barter 风格的双栏、条款槽和双方支持度。
- UI 只编辑提案草案，不直接修改外交状态。

验收标准：打开、取消、返回、提交和重新进入均稳定，鼠标焦点不会穿透到底层王国界面。

### 第 6 批：外交 AI

- 迁移每周提案行为和 AI 回应。
- AI 使用与玩家相同的合法性、评分、投票和执行入口。
- 扩充 AI 可生成的组合条款，但限制不合理或互相冲突的组合。

验收标准：AI 提案不使用隐藏特权，也不会通过重复提案绕过冷却。

### 第 7 批：清理依赖

- 从 `ModifiedPolitics.Main` 移除全部外交注册。
- 删除或保留为兼容转发器的旧类。
- 将战争潜力、战争倾向暴露为稳定只读接口。
- 移除 `ModifiedDiplomacy -> ModifiedPolitics` 临时依赖。

## 每批迁移规则

1. 先移动没有存档字段的纯模型和工具，再移动行为与 UI。
2. 每次只切换一个明确功能，保留可回退的提交。
3. 旧类停止注册后才能启用新类，禁止双重事件订阅。
4. Harmony 补丁移动时必须同时更换唯一 ID，并确认旧程序集不再包含该补丁。
5. 所有代码日志使用英文；中文显示文本进入本 Mod 的汉化文件。
6. 每批至少验证启动、加载旧存档、运行数日、保存并重新加载。
7. 用户负责本地编译和游戏测试；代码提交前记录本批迁移范围和测试点。
