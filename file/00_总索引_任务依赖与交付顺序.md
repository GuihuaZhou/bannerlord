## 0. 本包要解决的问题

既有 AI 兵力管理由原版 `GarrisonTroopsCampaignBehavior`、原版招募 `RecruitmentCampaignBehavior` 的 Mod Patch、`AiRecruitmentBehavior`、`DemobilizationBehavior` 和其他直接调兵路径共同触发。虽然取兵和捐兵已有不同执行组件，但没有统一的**任务决策权**和**转移批准权**，会出现重复触发、目的地与实际库存不一致、驻军兵种不均以及某些调拨不产生日志等问题。

**目标架构**：

```text
AiForcePlanningBehavior（每日任务、路线、存档）
  → AiForcePlanningModel（任务/兵源与定居点可行性评分）
      → PartyForceTargetModel（唯一人数目标；原实现保留）
      → WarRestPolicyModel（只在战争中的休整）
  → PartyForceTask（Recruit / WarRest / Maintain / Suspended）
  → PartyExchangeBehavior（自然访问和驻留期唯一调度入口）
      → PartyExchangeModel（现有兵员跨Party转移计划/批准）
      → AiTroopRecruitmentModel（新增士兵/雇佣兵/俘虏准入；原模型更名）
  → PartyExchangeService（编排、复核、提交、日志）
      → TroopTransferService / FiefPartyManager / 现有雇佣兵购买组件
```

**强约束**：针对统一管理的 AI 领主 Party，原版不得再自主决定或执行驻军取兵、驻军捐兵、普通补员；原版和旧 Mod 的行为入口不得绕开相应 Model 作独立审批。不得对非目标Party“一刀切”取消原版机制。

## 1. 已确定、禁止重复设计的规则

- 兵力目标：现有 `ForceManagement/Models/ForceManagementModels.cs:PartyForceTargetModel.Evaluate()` 与 `ForceManagementFacade.GetPartyTarget()`。和平 `0.35`、至少50；战争按 Clan `WarDisposition`；保护自有封邑用 `OwnFiefDefenseTargetRatio=1.00`。现有函数在战争倾向20附近有跳变，本次**不改公式**。
- 文化偏好：保留 `militaryConfig.xml` 的 `Fief / Professional(GarrisonTransfer) / Mercenary` 文化相对权重，以及 peace/war/siege/broke/critical 情境倍率。先确认真实可行兵源，再按偏好、效果、距离、安全性排序。
- 休整：**仅战争期间允许主动 WarRest**；和平裁军是既有独立特性，不等于 WarRest，默认开启状态不得擅自修改。
- 调拨类型：Mobile↔Garrison、Fief↔Mobile；定居点访问还统一协调 Mercenary 招募。俘虏招募保留独立资格/归顺流程，复用 `AiTroopRecruitmentModel`，不得硬塞入 PartyExchangeModel。
- 原有封邑批次 `FiefServiceBatch`、Hearth、冷却 `FiefReturnBatch` 和回滚继续由 `FiefPartyManager` 管理。Fief数据 `_fiefParty` 当前引用民兵Party的MemberRoster，不能假设独立普通MobileParty。
- 不启动默认关闭的**纯兵种互换**：当前 `EnableAutomaticSwap=false` 且 `Exchanges=DisabledPartyGarrisonExchangeModel()`；普通单向流转必须不依赖这个旧开关。
- 所有诊断记入文件日志，不在UI叠加异常信息。

## 4. 跨文档工程标准

1. `Model`纯读取/生成计划，不能修改Roster、Campaign移动目标、Hearth及存档。
2. `Behavior`负责事件、任务所有权、幂等与生命周期，不能内联复杂兵种打分。
3. `Service`执行前再核对持有者、编制、批次、兵种、伤兵、战争/战斗、财政和计划版本；按真实结果记录日志。
4. 强调守恒与幂等。一个士兵不能因重放事件在两个Roster中同时存在；封建兵转移另需批次/Hearth守恒。
5. 任务只能覆盖自己发出的低优先级命令，不能劫持原版军团、围城、追击、玩家任务。
6. 所有切换代码均有静态/测试开关和回退方案；切换不应留两套AI同轮执行。
7. 保留已使用的存档键；更名类时迁移行为类型需谨慎，不能仅改C#类名就假定旧存档可读。
