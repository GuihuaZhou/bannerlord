# Bannerlord 统一外交 API 与组合外交体系设计

## 1. 设计目标

ModifiedPolitics 的外交体系应当从本体单提案模式扩展为支持多项条款的组合外交，同时保证玩家界面、AI 行为、王国投票和最终执行使用同一套规则。

整体结构为：

```text
战争潜力 / 战争倾向 / 宗藩状态
              ↓
统一外交 API
  宣战 / 和平 / 同盟 / 贸易 / 宗藩
              ↓
单项条款评估器
              ↓
组合提案评估器
  Clan 逐项评分 → 组合修正 → 王国支持度
              ↓
王国投票
              ↓
统一执行器
```

组合外交不能绕过统一外交 API，也不能为宣战、和平等行为建立另一套互不一致的评分。

## 2. 统一外交 API

建立统一的外交评估入口，例如：

```text
KingdomDiplomacyEvaluationService

CanPropose(action, actor, target)
EvaluateForClan(action, actor, target, clan)
EvaluateForKingdom(action, actor, target)
Execute(action, actor, target)
```

以下系统必须调用同一入口：

- 本体外交按钮；
- 宗藩外交按钮；
- 组合外交；
- AI 外交；
- UI 预计支持度；
- 王国正式投票。

同一个 Clan 对同一项外交行为，不应因为入口不同得到不同结果。

### 2.1 单项评估结果

每次评估应返回统一结果：

```text
DiplomaticEvaluation
├─ 是否允许提出
├─ 禁止原因
├─ 本体基础分
├─ 战争潜力修正
├─ 战争倾向修正
├─ 宗藩关系修正
├─ 条约关系修正
├─ 战争风险修正
├─ 最终支持分
└─ 可供日志和 UI 展示的明细
```

## 3. 四项基础外交

### 3.1 宣战

```text
宣战支持度
= 本体宣战支持度
+ 战争倾向
+ 相对战争潜力
+ 战争目标价值
- 当前战争压力
- 新增多线作战风险
- 宗藩义务与限制
```

规则：

- 战争倾向越高，越支持宣战；
- 战争潜力不能只看绝对值，需要比较双方及其宗藩集团；
- 已参加多场战争时，应显著反对新增战争；
- 傀儡不能独立宣战；
- 附庸不能向宗主宣战；
- 和平后三周内，AI 不能再次提出对同一国家宣战。

### 3.2 和平

```text
和平支持度
= 本体和平支持度
- 战争倾向
- 战争潜力优势
+ 战败压力
+ 多线作战压力
+ 财政压力
+ 领土损失压力
+ 俘虏与赔款收益
```

规则：

- 战争倾向越高，越反对和平；
- 战争潜力低、战争进展差、财政恶化时更支持和平；
- 本体强制分支应逐步取消特殊豁免，或者明确标记为不可修改规则；
- 割地、赔款和释放俘虏属于组合条款，不应混入和平基础分。

### 3.3 同盟

```text
同盟支持度
= 本体同盟支持度
+ 共同敌人价值
+ 对方军事潜力
+ 对方战略位置
- 被拖入战争的风险
- 对方敌国总压力
- 宗藩限制
```

战争倾向对同盟的影响应当较弱：

- 好战 Clan 可能支持与强国结盟共同作战；
- 厌战 Clan 可能支持防御性同盟；
- 不能简单用战争倾向正负直接加分，应结合共同敌人和战争风险。

宗藩规则统一为：

- 傀儡不能签订同盟；
- 附庸不能签订同盟；
- 已有同盟在成为臣属时解除。

### 3.4 贸易

```text
贸易支持度
= 本体贸易支持度
+ 预期贸易收益
+ 和平稳定性
- 战争风险
- 宗主敌国限制
```

战争倾向和战争潜力只应间接影响贸易：

- 战争倾向高且双方存在严重冲突时，小幅降低支持；
- 当前参与大量战争时，降低贸易稳定性；
- 战争潜力只影响协议能否长期维持，不直接决定贸易价值。

否则可能出现军事强国天然更愿意贸易等不合理结果。

## 4. 宗藩 API

宗藩关系同样通过统一 API：

```text
EstablishVassal
EstablishPuppet
ReleaseVassal
ReleasePuppet
DeclareIndependence
```

### 4.1 建立附庸或傀儡

建立宗藩关系分为两个方向：

- 宗主要求对方臣服；
- 对方主动请求臣服。

双方的计算重点不同。

臣属国评估：

```text
臣服支持度
= 军事危机
+ 战败程度
+ 外敌压力
+ 宗主保护能力
- 主权损失
- 长期贡赋
- 自身战争潜力
- 好战倾向
```

宗主国评估：

```text
接纳支持度
= 臣属军事价值
+ 战略领土价值
+ 贡赋收入
- 接管其战争的风险
- 控制成本
```

傀儡比附庸承担更大的主权损失，因此必须更难接受。

### 4.2 解除关系与独立

需要区分以下行为：

- 宗主解除臣属关系：宗主单方面决议，不需要臣属同意；
- 臣属宣布独立：臣属单方面决议，通过后与宗主开战；
- 双方和平协商解除：可以作为双边组合提案；
- 傀儡违背宗主战争政策：自动转为独立战争。

## 5. 条款分类

组合外交必须区分双边协议、单方面行为和条件性最后通牒。

### 5.1 双边协议条款

以下条款必须获得双方同意：

- 和平；
- 贸易；
- 同盟；
- 建立附庸；
- 建立傀儡；
- 和平解除宗藩；
- 金钱；
- 割让领土；
- 释放俘虏；
- 要求对方加入第三国战争。

### 5.2 单方面外交行为

以下行为不需要对方同意，只需要行为国投票：

- 宣战；
- 撕毁贸易协定；
- 撕毁同盟；
- 宗主解除臣属；
- 臣属宣布独立。

### 5.3 条件性最后通牒

最后通牒作为后续独立功能，例如：

```text
交出城镇并支付赔款，否则宣战
```

宣战不应作为普通双边谈判条款要求敌人同意。

因此，当前组合外交中的宣战应重新定义：

- 普通组合协议中不能添加宣战；
- 宣战应进入单方面外交决议；
- 或者作为未来最后通牒被拒绝后的后果。

否则会出现对方必须先同意被宣战的问题。

## 6. 提案流程

### 6.1 双边提案

```text
编辑提案
→ 完整合法性检查
→ 接收国模拟投票
→ 接收国不接受：谈判通道关闭
→ 接收国接受：提交提案国正式投票
→ 投票通过
→ 执行协议
```

玩家是接收方时：

```text
AI 提案国模拟本国意见
→ 玩家王国真实投票
→ 玩家最终决定
```

不需要让两个王国连续弹出两次正式投票。一个真实投票加另一方模拟接受即可。

### 6.2 单方面决议

```text
选择单方面外交行动
→ 本国王国投票
→ 通过后立即执行
→ 通知目标国
```

单方面决议不计算目标国是否接受。

## 7. 组合支持度

### 7.1 Clan 评分

统一采用：

```text
总分 > 0：支持
总分 = 0：中立
总分 < 0：反对
```

取消组合外交当前额外设置的固定接受门槛，所有条款分值保持在同一量级。

### 7.2 王国支持度

继续使用影响力作为权重：

```text
支持权重 = 支持提案 Clan 的影响力总和
总权重   = 全部有效 Clan 的影响力总和
支持率   = 支持权重 / 总权重
```

预计支持率超过 50%，代表普通多数支持。

正式投票仍由本体投票平台处理，允许玩家使用影响力压制反对意见。

### 7.3 条款组合修正

组合提案不能只机械相加，需要额外计算：

- 和平加赔款：赔款提高战胜国接受度；
- 和平加割地：割地提高接收方、降低割让方支持度；
- 同盟加加入战争：参战风险必须计入同盟价值；
- 臣服加贡赋：贡赋增加宗主收益、降低臣属支持；
- 多座城镇同时割让：需要累进惩罚；
- 领土和金钱不能无限线性叠加，避免用巨额金钱轻易买下国家主权。

## 8. 执行模型

严格原子事务在游戏本体中难以实现，因为外交 Action 通常不可回滚。

因此，应将执行语义定义为：

> 预检完整、执行幂等、失败可恢复的准事务，而不是绝对原子事务。

执行流程：

1. 锁定提案；
2. 检查全部条款；
3. 生成固定执行计划；
4. 保存执行记录；
5. 按顺序执行；
6. 每完成一项就保存进度；
7. 中断后从未完成条款继续；
8. 已完成条款不得重复执行。

推荐执行顺序：

```text
解除冲突协议
→ 和平
→ 建立贸易 / 同盟 / 宗藩
→ 加入第三国战争
→ 释放俘虏
→ 转移土地
→ 支付金钱
```

宣战和独立不与普通双边协议共用这套执行顺序。

## 9. AI 外交

AI 和玩家必须使用完全相同的：

- 合法性检查；
- Clan 评分；
- 王国支持率；
- 条款执行器。

AI 只额外拥有如何构造提案的策略。

建议分阶段支持：

1. 和平加赔款、释放俘虏；
2. 和平加割地；
3. 贸易加金钱；
4. 同盟加加入战争；
5. 臣服加赔款或贡赋条件；
6. 解除协议；
7. 最后通牒。

不应为 AI 另写一套简化接受公式。

## 10. 重构顺序

### 第一阶段：统一底层评估

- 建立统一外交评估服务；
- 接入宣战、和平、同盟、贸易；
- 统一战争倾向和战争潜力；
- 修正附庸同盟规则；
- 暂不改变现有 UI。

### 第二阶段：整理条款分类

- 区分双边条款与单方面行为；
- 将宣战移出普通双边提案；
- 明确解除条约、解除宗藩和独立的投票对象；
- 清理冲突组合。

### 第三阶段：统一组合评分

- 删除重复评分入口；
- 统一 Clan 接受阈值；
- 加入条款组合修正；
- 确保 UI、AI 和正式投票显示同一结果。

### 第四阶段：整理执行器

- 明确准事务语义；
- 固定执行顺序；
- 处理失效、重试和放弃；
- 防止部分执行造成重复扣款或重复转移。

### 第五阶段：完善 AI 与 UI

- AI 使用统一提案构造器；
- UI 显示 Clan 支持明细；
- 显示各条款分数和主要反对原因；
- 最后实现自动平衡与最后通牒。

## 11. 核心原则

外交规则与组合提案必须彻底分开：

- 统一外交 API 决定每个外交动作是否允许、对每个 Clan 有多少价值以及如何执行；
- 组合外交只负责把多个动作打包、计算整体政治结果、组织投票并提交执行；
- UI、玩家、AI 和日志必须读取同一份评估结果；
- 不允许为不同入口分别维护含义相近但结果不同的外交计算。
