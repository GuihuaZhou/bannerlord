# W1：退役 ReinforcementMissionService 清理与存档边界

## 目的与明确结论

最新 `main@66c75728` 中旧 `ReinforcementMissionService` 不构成新运输调度入口：`IsProtected()`、`MayStartReinforcement()`、`TryRegister()` 都直接返回 `false`；它和 `IArmyMissionProtectionModel` 仍由 `ForceManagementFacade` 挂载。新的运输是 `ReinforcementTransportBehavior` + `ReinforcementPartyComponent` + `ReinforcementTransferService`。

用户不要求再维持退役 Service 的旧业务接口；**同意删服务，但不允许把旧存档编号随意重分配**。

## 必须核对的源码

- `ForceManagement/Services/ReinforcementMissionService.cs`，旧 `GetMission/GetActiveMissions/RefreshSources/GetInboundTroopCommitment/Restore/Complete/Cancel` 与永远返回 `false` 的接口。
- `ForceManagement/Behaviors/ReinforcementMissionBehavior.cs`，`SyncData("modifiedarmy_reinforcement_missions", ref _missions)`；`OnGameLoadFinished` 取消旧任务。
- `ForceManagement/Contracts/ForceManagementTypes.cs`：`ReinforcementMissionState`、`ReinforcementCancelReason`、`ReinforcementMission`、`IArmyMissionProtectionModel`。
- `ForceManagement/Services/ForceManagementFacade.cs`：`ReinforcementMissions`、`ArmyMissionProtection` 属性及构造注册。
- `Fief/Models/FiefPartyManager.cs` 中 `FiefSaveDefiner`：`AddClassDefinition(typeof(ReinforcementMission), 8)` 和 `ConstructContainerDefinition(typeof(List<ReinforcementMission>))`；`ReinforcementPartyComponent` 已在 9。
- **先全文检索** `ReinforcementMission`、`ReinforcementMissions`、`ArmyMissionProtection`、`ReinforcementCargo`、`FoodTransfers`、旧存档键；不要仅凭类名认为所有相关服务都必须删除。

## 实施拆分

### W1-A — 立即清理：无效运行服务

1. 删除 `ReinforcementMissionService.cs` 的现有运行逻辑；删除 `IArmyMissionProtectionModel`，清理 `ForceManagementFacade` 中仅指向旧 Service 的字段和初始化代码。
2. 修改 `ReinforcementMissionBehavior` 的旧服务 `.Restore(...)` 依赖，使其不再引用已删 Service。
3. 评估 `ReinforcementCargoService` / `FoodTransferService`：当前只见旧 `ReinforcementMission` 作为入参，若无任何活动调用才删；若有使用则单独迁移到新运输真实实现，禁止误删。
4. 如 `ReinforcementMissionBehavior.StartControlledMission()` 无调用，直接删除。
5. 确保 `ReinforcementTransportBehavior` 与 `ReinforcementPartyComponent` 不受影响，**不要改后者的保存字段与编号**。

### W1-B — 旧存档兼容：单独决策

推荐采用最小历史类型占位方案：

- 保留旧 `ReinforcementMission` 的序列化签名与类型编号 **8**，保留列表容器定义（或使用具有相同兼容效果的注册方式；必须实机验证），**只是不再保留旧业务 Service**。
- 暂保留轻量 `LegacyReinforcementMissionSaveBehavior`（可以由原 `ReinforcementMissionBehavior` 改为），仅读取旧键并清空/注销旧任务，不允许其重新派遣、移动或转移真实兵员。其作用是存档迁移而非活跃功能。
- 用户已愿意不兼容很早的存档；如决定彻底删除旧类型/Behavior，必须单列“破坏兼容”的 PR，在**多个当前正在使用的真实存档**上做删除后加载测试；不得声称因为新版本已经保存多次就能保证旧 SaveDefiner 数据一定不再出现。
- 现有旧类/旧占位建议标 `[Obsolete("Legacy save compatibility only")]` 并放入明确的 `LegacySave/`，待用户正式确认不再需要兼容再删。

### W1-C — 死代码删除的边界

- **必须保留**：`ReinforcementTransportBehavior`、`ReinforcementPartyComponent`、`ReinforcementTransferService`、`ReinforcementDispatchModel`，以及新运输实际调用的 `TransportThreatModel`。
- 不要把两种名称相似的“旧领主增援任务”和“新驻军运输部队”当成一个东西。
- 移动或重命名 `SaveableRootClass(9)` 的命名空间/类时要优先确认序列化类型标识稳定，不在这一阶段做。

## 验收

1. 全项目无旧 Service / `IArmyMissionProtectionModel` 编译引用。
2. 自己创建新运输任务，出发、交付、返程/回收正常；读档中途任务能恢复。
3. 当前真实存档可加载，旧任务不会重新动作或凭空生成士兵。
4. `SaveableRootClass(8)` 历史占位不被新类重用；编号 9 不变。
5. 任何试图删旧存档登记的提交，都必须给出存档测试证据与回退方案。
