# W3：征粮队修复的日志规范、联合回归与验收清单

**范围**：普通征粮队及相同 SupplyPartyComponent 所支持的跨城援粮路径。  
**目标**：无需逐小时倾倒变量，也能确认何时口粮不足、谁更改了路线、伤员为何增加，以及任务是否最终完整结算。

## 1. 统一的中文自然日志

- 使用 `GameTexts.FindText` + `TextObject.SetTextVariable` + 语言文本配置，不直接把长期英文硬编码的事件码、`true/false`、`DefaultBehavior`、`SourceClanNull` 等发给普通用户。
- 采用“谁、在哪里、做了什么、结果如何、为何失败”的完整中文短句，数字使用“人、单位粮食、天”等单位；源码类名可只在 Debug 中出现。
- 只能在关键事件及**状态变更时**打日志，普通无人为变化的每小时巡检安静。
- `Info`：正常派遣、粮源完成采购、到家结算；可以 `FileInfo` 防止刷屏。
- `Debug`：需求配粮、真正实发、速度量纲、任务状态、目标命令变更和伤兵快照。
- `Warn`：连续无法出发、实发口粮低于安全值、行程已经断粮、有证据的反复折返、避险无效。
- `Error`：回滚失败、库存或兵员不守恒、无法安全回收等真正内部错误。

### 1.1 示例（消息为模板，不代表发生过）

```text
[Info] [征粮队] 胡比亚派出了50名护卫前往恺拉征粮，已从驻军粮仓带走18单位粮食，预计可维持7天。
[Debug] [征粮队口粮] 胡比亚征粮队每天预计消耗2.5单位粮食，往返预计5天，另预留2天；需要18单位，粮仓实际配给18单位。
[Warn] [征粮队] 胡比亚原计划派往恺拉的征粮队未能出发，因为粮仓只有4单位可用粮食，少于预计需要的18单位。护卫已经归队。
[Debug] [征粮队路线] 胡比亚征粮队正在前往恺拉，原版行为曾把目的地改成胡比亚。当前没有发现敌军威胁，征粮任务已恢复原目的地。
[Warn] [征粮队路线] 胡比亚征粮队在一天内连续3次改变目的地，已记录各次移动命令，可能存在路线控制冲突。
[Debug] [征粮队状况] 胡比亚征粮队今天有50名护卫，其中4名伤员；剩余粮食2单位，预计能吃不足1天，当前处于饥饿状态。伤员变化原因尚未确认。
[Info] [征粮队] 胡比亚征粮队从恺拉购得60单位粮食，花费了900第纳尔，正在返程。
[Info] [征粮队] 胡比亚征粮队返回驻军，带回48名护卫及58单位粮食，任务已经完成。
```

## 2. 可追踪数据和采样频率

| 时机 | 必填 | 等级 |
|---|---|---|
| 派遣尝试结果 | 部队 ID、驻军、粮源、护卫数、口粮需求、可取、实际领取、失败原因 | Info 成功；连续失败 Warn；详细计算 Debug |
| 每日部队健康快照 | 世界日、人数、伤兵数、粮食数、`FoodChange`、预计可食用天数、`IsStarving`、战斗状态、当前目标 | Debug；变化才打印 |
| 目标真实变化 | 世界时、旧目标、新目标、默认/短期 AI 行为、危险标志、发令来源 | Debug；反复折返 Warn |
| 危险开始/解除 | 敌强判定/native 逃避标志、暂停期限、恢复原目标 | Debug；无法避险 Warn |
| 粮源采购 | 采购粮食、花费、护卫所持粮食、是否换站/返航 | Info |
| 返回与结算 | 出发50人、返还健康/伤员、食物剩余、移动到驻军的净值、金币/驮畜 | Info；数据不守恒 Error |

若对“新增伤兵”做归因，需明确：成员名单、`WoundedNumber` 前后变化、同时发生战斗/饥饿/医疗等事件。数据只能证明发生先后；未经明确战斗或伤员事件不得写“饥饿直接造成受伤”。原版饥饿可能导致士气、逃兵等，并不自动证明伤员增加由饥饿引起。

## 3. 两个 Worker 的接口协作

W1 和 W2 都会编辑 `SupplyPartyBehavior.cs`。避免一人用旧版本覆盖另一人：

1. W2 首先提交**只读日志补丁**供实验；W1 并行设计并在独立分支实现配粮和兜底。
2. 集成时先将 W2 诊断合并至 W1，保留该日志观察至少一次原始折返；如两者均加 `OnHourlyPartyTick` 监控，应合并成只读一次快照，不重复计算危险判定。
3. W1 食物和 W2 路线修复完毕后分别提交增量，W3 编译统一分支并进行联合测试。
4. 如果 `TryDispatchControlledAid` 与 `CanOrganizeLocalForaging` 出现派遣循环，先停止自动回归，保留日志，不通过硬编码一刀切关闭跨城援粮。

## 4. 详细联合验收

### 4.1 经济和食物守恒

- [ ] 真实驻军粮仓减少量 = 征粮队取得真实食物量，发车前不得出现负库存。
- [ ] 采购消耗对应来源库存减少和经济支付，不能凭空生成粮食。
- [ ] 护卫消耗的口粮不会在返程“再退回”，已购粮食和剩余食物不重复算。
- [ ] 出发失败恢复全部护卫、坐骑和可退费用，无重复队伍和滞留物品。
- [ ] 无粮仓口粮不能出发且不会因冷却直接屏蔽可行的跨城援粮。

### 4.2 行为和路径

- [ ] 静态安全路线连续72小时不会无理由折返。
- [ ] 短期敌情允许原版避险；敌情结束后按任务恢复，不因定时重申而打断撤退。
- [ ] 粮源失效、城池易主、围城、运输队战败、读档恢复都可稳定处理。
- [ ] 同一来源多支征粮队不重复消费来源粮食。
- [ ] 本地征粮与跨城援粮互不抢占任务标识、兵力和粮食。

### 4.3 伤员和日志

- [ ] 每日伤员统计明确健康/受伤/总数，不把“伤员绝对数增多”错误叙述成饥饿造成。
- [ ] Debug 开启时可以重建一次折返的触发行为、对象、时刻和处理结果。
- [ ] 默认 Info 文件不会刷每小时快照；重要成功事件可见，正常等待低噪音。
- [ ] Warn 只对实际断粮、真实反复冲突或其它异常发出，限频；无错误码漏到普通中文文案。
- [ ] 中文文本中的变量在所有语言版本都赋值，不出现空定居点、空兵种、字面占位符。
