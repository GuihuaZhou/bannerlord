4. `PartyFinance` 合并到 `PartyManagement`；不保留顶层 `PartyFinance`。

## 开工与提交规则

1. 各 Worker 先 `git rev-parse HEAD` 并将 SHA 写进 PR；若不是上述 SHA，应对比差异、列出冲突。
2. PR 必须附“迁移前后行为对照表”、源码修改文件清单和被保留的 SaveId / Harmony 目标方法清单。
3. 每个 PR 只处理一个主题；移动文件优先 `git mv`，逻辑变更另提交。
4. 没有编译条件时，不能宣称“编译通过”，需记录阻塞环境。
5. `Main.cs` 的奖励逻辑及两个指定文档/脚本不在任何 PR 的文件变更清单中。
6. 不允许把 `null`、空 Clan 或不安全行为当作重构时的“方便回退”；旧权限检查必须被严格保留。
