# 05｜原版及旧Mod自主兵力行为禁用与新入口原子切换

> 项目：`GuihuaZhou/bannerlord` · 基线：`main` / `4ae5ff66084efa33e362c13ee7f8b686a22c17ab`（2026-10-22 核对）。
> 状态：**实施计划；并非代码已经修改或测试通过**。Worker 开始前必须读取最新仓库 HEAD；如果源码发生变化，以当时实际代码为准并报告差异。
> 范围：`ModifiedArmy/ModifiedArmy/`；除注明外均以此为相对路径。

## 1. 这是受控切换任务，不能先做

要求01–04相关可运行新路径和可核对的执行结果齐备后，**在同一集成版本**关闭原版与旧Mod平行决策，并启用单一调度。不得先只把原版`OnSettlementEntered` Prefix 改成 `false`，否则可能使AI驻军调兵中断。

## 2. 明确现有两套路径

```text
原版：GarrisonTroopsCampaignBehavior.OnSettlementEntered
  → ManageGarrisonForParty / ManageGarrisonForArmy
  → TakeTroopsFromGarrison / LeaveTroopsToGarrison
  → 当前Mod Harmony Prefix替换部分真实操作

Mod：RecruitmentCampaignBehavior.OnBeforeSettlementEntered
  → CheckRecruiting（原版可能重复调用）
  → AiSettlementRecruitmentPatch.Prefix
  → TryTransferFromGarrison / TryRecruitFief / TryRecruitLordMercenary

另有：GarrisonTroopDonationPatch.Postfix
  → PartyGarrisonExchangeBehavior.OnNaturalVisit（当前自动换兵禁用）
  → DemobilizationBehavior.OnNaturalVisit（和平复员独立）
```

原版 `GarrisonTroopsCampaignBehavior.RegisterEvents`仍注册 `SettlementEntered`。其原版`OnSettlementEntered`还承担军团驻军交换。`GarrisonTroopDonationPatch.Prefix`现在对部分AI返回`true`；`TakeTroopsFromGarrison`本身被另一个Prefix转发到 `TransferApprovedTroopsFromGarrison` 并跳过原版循环。这些都是要清除的**决策或旧桥接入口**。

## 3. 唯一新定居点入口

将 `ForceManagement/Behaviors/PartyGarrisonExchangeBehavior.cs` 改为 `PartyExchangeBehavior`，建议由它**独立注册** `CampaignEvents.SettlementEntered` 和用于驻留多日的安全日Tick。若选择保留Harmony Postfix桥接则不得再注册相同事件监听；首选独立Behavior事件监听，Harmony只负责阻止原版调度，**两者不能并存**。

新入口：

```text
SettlementEntered / 合法驻留DailyTick
  → IsModManagedAiParty / 访问合法性
  → PartyForceTask状态 + 当天本次访问幂等Key
  → PartyExchangeModel.BuildPlan (或新增招兵审核)
  → PartyExchangeService.Validate+Execute
  → 更新任务进度/账本/日志
```

对同一次访问所允许的多兵源操作，先统一建立剩余额度，执行一次后更新快照；Recruit只做合法补员，WarRest只执行合法返乡/捐兵。避免先捐再抽、先还再征。普通单向调兵不需开启 `EnableAutomaticSwap`。

## 4. 禁用原版与旧Mod行为的精确清单

| 调用入口 | 修改要求 | 保留边界 |
|---|---|---|
| `GarrisonTroopsCampaignBehavior.OnSettlementEntered`（Harmony位于`Garrison/Patches/GarrisonTroopDonationPatch.cs`） | 对受Mod统一管理的AI领主与军团相关调兵分支 Prefix拒绝原版执行 | 不禁用原版新局初始化驻军、所有权变化和其他非调兵工作 |
| `GarrisonTroopsCampaignBehavior.TakeTroopsFromGarrison` Harmony | 移除作为AI批准调拨入口的旧实现；必要保留范围外兼容防线 | 不能让旧Postfix继续重复记日志 |
| `GarrisonTroopsCampaignBehavior.LeaveTroopsToGarrison` Harmony | 移除AI依赖原版计算捐兵的人数与兵种路径 | 新占领驻军供给、军团/其他专用行动须走显式Model目的类型 |
| `RecruitmentCampaignBehavior.CheckRecruiting`（`Recruitment/Patches/AiSettlementRecruitmentPatch.cs`） | 对受管理AI阻止原版自主招兵；删除旧Patch内部 `TryRecruitFief/TryTransferFromGarrison/TryRecruitLordMercenary`执行权 | 商队与其他不在管理范围的角色，保留原版或当前有效处理；玩家手动不受影响 |
| `AiRecruitmentBehavior.OnDailyTick` | 切换为新 `AiForcePlanningBehavior` 任务调度 | 旧Behavior不可同时发路线命令 |
| `PartyGarrisonExchangeBehavior.OnNaturalVisit`旧调用 | 转到新的唯一 `PartyExchangeBehavior` | 删掉双重Postfix/独立Listener重复触发 |
| `DemobilizationBehavior.OnNaturalVisit`旧调用 | 旧和平复员不再同轮独立调兵；统一审批/调度 | 保留和平复员政策、存档和已有单独开关 |
| `RecruitPrisonersCampaignBehavior.RecruitPrisonersAi` | 检查既有 `PrisonerRecruitmentPatch.cs` 已代理统一招募准入；不得因本次切换恢复原版绕过 | 俘虏特殊Conformity、定价及敌方野怪过滤独立，不移入PartyExchangeModel |

**重点**：要审核 `ReinforcementCargoService`、`ReinforcementTransferService`、`DisbandSettlementService`、`DisbandPartyGarrisonMergePatch`等直接触碰Roster路径；正常AI主动调拨必须经统一Model；特殊已批准任务（跨城运输、战后新占领、整支Party解散）也须有明确Operation/Purpose及授权Model，不能悄悄保留无审批通道。具体特殊任务不能在本次盲目删除，否则会破坏既有功能。

## 5. 定义Mod管理范围

建议专门提供 `IsModManagedAiParty(party, operation)`，统一检查：非玩家直接控制主Party、有效AI领主/Clan、可处理的实际状态、玩家Clan同伴是否允许自动兵力管理、军团指挥和玩家专用命令例外。

**用户要求禁用原版相关行动，不等于禁用全游戏所有Party原版行为。** 列出每种非目标Party的回退路径，确保商队、玩家、野怪、村民没有因全局 Prefix返回false而失去其原有独立行为。

军团领导者的 `ManageGarrisonForArmy`要有Mod显式替代策略；不能因为暂时不做军团交换而默认全部归普通Party逻辑。新占领城镇的战后驻军补充同样必须显式处理。

## 6. 逐步启用与保守失败

- 引入清晰的总开关（例`EnableUnifiedAiForcePlanning`，名称需和既有XML解析兼容），默认开发期为false。切换时**新入口与旧入口绝不同时执行**。
- 可加入只记录审批但不执行的影子模式；它不得持有任务路由、不能扣费或动Roster。
- 一旦总开关启用，Mod管理范围内的原版/旧Mod调兵始终被封锁；新Model临时失败时应给出拒绝原因并保持现有Roster，不得偷偷回退原版自行取兵。
- 极端故障的回退是整个版本/配置的受控回滚，而不是同一次访问分别调用新旧算法。
- 拦截前后查 `Harmony.GetPatchInfo`或同等工具，记录冲突补丁优先级，尤其其他Mod对同一原版私有方法的补丁。

## 7. Worker验收

- [ ] 一次自然访问仅一条统一调度日志；不存在两次交易或反向交易。
- [ ] `CheckRecruiting()`被重复调用7次也不会触发旧Fief/Garrison/Mercenary执行。
- [ ] 有兵源的合法AI Party仍能补员；有超额兵且Garrison有空间时仍可捐兵。
- [ ] 军团访城、战后新占领、任务保护均有显式Model拒绝或批准，不凭原版隐式执行。
- [ ] 玩家主Party手动调拨、商队招募、初始化驻军、俘虏处理不受误伤。
- [ ] 若审批失败，Roster不动、文件日志可追踪；不回退原版随机选兵。
- [ ] `EnableAutomaticSwap=false`时单向转移照常可用、纯兵种互换不可用。
- [ ] 同日和平复员、WarRest、Recruit不可能重复互相执行。
