# ModifiedArmy 日志文案、严重等级与中文本地化统一方案

## 1. 设计目标

所有面向玩家的日志采用自然口语化中文完整句子，避免 `op=`、`|`、`Total≤`、`False`、`null`、`Debug类名` 等内部格式；保留正常的中文标点、数字、单位和必要的百分比。标准前缀如 `[统一调兵]` 可以保留作为**事件类别**，正文禁止堆叠字段和内部符号。别用“批准0人，但没有执行”这类重复叙述，要说清实际动作方向和真实原因。

所有玩家可见内容均从 `GameTexts.FindText`/`TextObject` 与本地化字符串取得，兵种/定居点/角色名直接传 `TextObject`。不要在 C# 代码里硬编码中文或英文句子。英文原文和简体中文语言文件使用同一组占位符 ID，以免换语言丢参数。必要的操作 ID、技术名仍可用 **Debug 详细诊断**，但文字说明同样为自然中文，不输出机器字段串。

## 2. 按调用渠道区分“日志等级”和“是否弹到游戏画面”

已核对 `ModifiedArmy/ModifiedArmy/Utils/ModLogger.cs`：`Debug/Info/Notice/Warn/Error` 既写文件，也按照 MCM 显示阈值显示；`FileInfo` 和 `FileNotice` 只写文件、不推送游戏消息。MCM 默认画面阈值为 Notice，文件阈值为 Info（如用户调成 Debug 才能看到全部调试内容）。`FileNotice` 写入 Notice 级别，不等于 Info。

| 等级 | 用途 | 推荐 API |
|---|---|---|
| Debug | 常规计算、非正常但可恢复的预期拒绝、候选详细诊断、测试过程 | `ModLogger.Debug`（默认画面不显示） |
| Info | 实际已发生的常规招募、征召、驻军补给、任务建立或完成、重要状态变化 | `ModLogger.FileInfo`；玩家确需游戏提示时再用 `ModLogger.Info` |
| Notice | 玩家需要注意的重要军事动态；单次较大规模调动、部队任务无法继续等重大但可控事件 | `ModLogger.FileNotice` 或 `ModLogger.Notice`（慎用） |
| Warn | 明显不应长期发生的异常：合法驻军归属校验丢失、连续多天关键补员失败、名册不一致、交通任务反复失败 | `ModLogger.Warn`；防止每次循环重复弹窗 |
| Error | 数据损坏、事务回滚失败、实际兵员数不守恒、严重异常导致功能无法使用 | `ModLogger.Error`，必须包含操作/Party/定居点上下文 |

严重等级依据**实际事件影响**，不依据 `ApprovedCount == 0` 一刀切：合理满编不招兵通常是 Debug；应有兵可调却由于内部字段缺失而拒绝，是 Warn。成功招募4人的日报是 Info 而非 Notice。

## 4. 本地化占位符自动检查：已确认6组不匹配

`submodule_strings.xml` 内部字符串 `id="str_modifiedarmy_*"` 的 `text` 以 `{=本地化Key}` 开头；`Languages/CNs/modifiedarmy-zho-CN.xml` 用的是**本地化Key**，而非 `str_*`，比对脚本必须用 `{=...}` 建立映射。`TextObject.SetTextVariable` 设置的是 `SETTLEMENT_NAME` 和 `TROOP_NAME`，译文必须使用**完全相同**的参数名。

| 本地化 Key | 中文译文的问题 | 修改要求 |
|---|---|---|
| ModifiedArmy_ManpowerConsume | 错用 `SETTLEMENT_ID`、`TROOP_ID` | 改为 `SETTLEMENT_NAME`、`TROOP_NAME`；保留明细 |
| ModifiedArmy_ManpowerProduceNoSupply | 错用 `SETTLEMENT_ID` | 改 `SETTLEMENT_NAME` |
| ModifiedArmy_ManpowerProduce | 错用 `SETTLEMENT_ID`，遗漏 `MANIFEST` | 改 `SETTLEMENT_NAME`，增加“本次训练的兵种为{MANIFEST}”等口语化明细 |
| ModifiedArmy_ManpowerRecruitmentBlocked | 错用 `SETTLEMENT_ID` | 改 `SETTLEMENT_NAME`，不要把多个布尔条件当成一句话 |
| ModifiedArmy_ManpowerRecruitment | 错用 `SETTLEMENT_ID` | 改 `SETTLEMENT_NAME` |
| ModifiedArmy_TransportEvent | 漏 `STATE`、`EVENT_AMOUNT` | 补回占位符或确认日志新语义后同步修改 C# 模板，两边必须一致 |

**特别提醒：** CN 文件对某些默认句子做了完全不同的覆盖：原始 `ModifiedArmy_ManpowerProduce` 已是含定居点名称及兵种清单的可读句子，而 CN 版本把它变成字段表，直接丢掉了 `MANIFEST`。优先修 CN 覆盖，不要误以为 C# 没有传名称。

## 5. 全局实现原则

- 保留现有的 `ModLogger` API 及 MCM 显示/文件阈值；不用把等级翻译为字符串后再记录。
- 在 UI 提示中保留事件分类，其余全部是完整自然句子，包含定居点和 Party 名称；日期由 logger 前缀提供，不再每条重复加“日期=92953”。
- 不在 Debug 字符串中用 `null/True/False/ID` 当最终文本；对于未知名字明确写“尚未取得名称”，并附内部 ID 的**另一个受限调试信息**（如果确有排障需要）。
- 相同事件以 Party、定居点、操作类型、失败原因、游戏日期限频；禁止仅按失败原因全局限频，导致其他 Party 丢失证据。
- 日志产出**必须只读**；不可调用重新执行审批或生产消耗的模型；对已经存在的计划、批准、执行结果拍快照。
- 任何 `Warn/Error` 要保留一次可关联的操作序号，用户句子可以说“本次调兵记录编号为……”而不暴露英文键值串。
