# 官职任命评分系统设计方案

## 一、设计目标

建立独立的官职评分模型，负责判断某个 Hero 担任某个官职的适合程度。

评分系统与官职资格、任命执行、官职收益完全分离。

职责划分：

  模块                         职责
  ---------------------------- ----------------------------
  OfficeRules                  判断 Hero 是否具备任职资格
  OfficeAssignmentScoreModel   计算 Hero 担任官职的评分
  OfficeAppointmentService     执行任命、撤职
  OfficeEffectService          提供官职实际收益
  OfficeAiBehavior             决定何时任命

## 二、评分模型

总体公式：

    FinalScore = AbilityScore + TraitScore + PoliticalScore + SpecialBonus

其中：

-   AbilityScore：技能能力
-   TraitScore：性格适配
-   PoliticalScore：政治因素
-   SpecialBonus：特殊身份加成

## 三、AbilityScore

原则：

-   只使用 Skills（技能）
-   不使用 Attributes（基础属性）

### 大元帅 Marshal

    Tactics × 3
    + Leadership × 3
    + Scouting × 2
    + Steward × 2
    + Engineering × 2
    + Charm
    + Trade

### 首席大臣 ChiefMinister

    Steward × 3
    + Trade × 2
    + Charm × 2
    + Leadership
    + Engineering

### 宫廷总管 CourtSteward

    Charm × 4
    + Leadership × 2
    + Steward × 2
    + Roguery

## 四、TraitScore

原则：

-   Traits 不决定资格。
-   Traits 不覆盖技能差距。
-   Traits 只作为辅助修正。

### 大元帅

-   Calculating
-   Valor
-   Honor

### 首席大臣

-   Calculating
-   Honor
-   Mercy

### 宫廷总管

-   Honor
-   Generosity
-   Mercy
-   Calculating

## 五、PoliticalScore

政治因素包括：

-   Hero 与君主关系
-   Clan Tier
-   Clan Influence
-   已拥有官职数量

政治因素用于 AI 任命倾向，不属于 Hero 能力。

## 七、核心职责

### OfficeRules

负责：

-   是否存活
-   是否俘虏
-   是否属于王国
-   是否已有冲突官职
-   是否满足职位限制

### OfficeAssignmentScoreModel

负责：

-   计算 Hero 对职位的评分
-   提供统一排序 API

接口：

``` csharp
float GetScore(
    Hero hero,
    OfficeType officeType,
    Kingdom kingdom);
```

### OfficeAppointmentService

负责：

-   任命
-   撤职
-   保存状态

### OfficeEffectService

负责：

-   官职实际收益计算

## 八、最终原则

1.  Skills 决定能力。
2.  Traits 决定性格适配。
3.  PoliticalScore 影响君主任命倾向。
4.  Attributes 不参与官职评分。
5.  评分 Model 独立，所有任命系统统一调用。
6.  Rules 管资格，Model 管排序，Service 管执行。

支持：

-   AI 自动任命。
-   玩家申请官职。
-   中央总督系统。
-   大元帅系统。
-   后续新增官职。
