## 二、Worker 独立任务

| ID | 优先级 | 任务 | 依赖 | 完成标准 |
|---|---|---|---|---|
| L1 | P0 | 修复中文日志占位符与统一话术 | 独立 | 全部日志占位符匹配，定居点和兵种名称不再消失 |
| L2 | P0 | 修复驻军 Clan 身份验证与调兵被拒绝 | 独立，先核验实际运行源码 | 同 Clan 双向调兵正常、异 Clan 安全阻断、没有凭空增兵 |
| L3 | P1 | 分类等级与频率治理 | 依赖 L1 文案规范 | 日志正常状态不刷屏，异常易定位，Info/Notice 不混用 |
| L4 | P1 | 调兵诊断的自然语言及双向操作审计 | 与 L2 协作；避免同时改同一方法 | 每次拒绝准确指出单个或多个根因，有唯一操作标识可追踪 |
| L5 | P1 | 增强驻军生产及批准0的解释能力 | 独立 | 区分容量、费用、工资、维护资金、未获得可用候选，不改生产数值 |
| L6 | P2 | 日志系统本地化与验收测试 | L1/L3/L4/L5 合并后 | zh-CN 与其他语言可正确展示；默认等级、过滤、节流测试通过 |

优先顺序：先合并 L1 和 L2，复测驻军调兵；随后 L4、L5；再 L3 全局调整及 L6 验收。并行时让 L2 独占 `PartyExchangeModel/PartyExchangeService` 的权限判断，让 L4 仅改日志格式与只读诊断入口，集成时合并。

## 四、不可触碰的行为边界

1. 普通日志重构不应改招募数值、兵力目标、财政公式、人口消耗、封邑兵身份或战斗规则。
2. Log 不得调用有副作用的招募审批、名册对账、生产消费或随机数，不得为打印消息重复执行模型。
3. P0 驻军身份修复仅作用于**真实驻军 Party**及**原有白名单目的**，不可对野战队伍或非同家族领主宽松放行。
4. `RecruitmentLogFilter` 已限制部分玩家王国相关消息；全世界的 Debug 逐定居点日志应另行加过滤/节流，不应让全地图逐兵营刷屏。
5. 如在用户本机运行源码和公开 main 存在分歧，以正在编译的实际代码为准；不能硬套行号或宣称源码已修改。
