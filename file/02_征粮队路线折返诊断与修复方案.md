# W2：征粮队每日折返——路线冲突诊断与定向修复计划

**范围**：`SupplyPartyComponent`、`SupplyPartyBehavior`、必要时针对原版定居点访问评分的窄范围 Harmony Patch。  
**基线**：`main@28f87c824ab07b4230e821052ae62e47e46ccf78`。  
**第一要求**：先判断谁改变了方向，避免把每次避敌都误判成 Bug。

## A. 代码事实与推断

1. 创建时 `SupplyPartyComponent.OnMobilePartySetOnCreation()` 执行 `MobileParty.Ai.SetDoNotMakeNewDecisions(false)`。读档的 `SupplyPartyBehavior.OnGameLoadFinished()` 也设置 false。
2. 任务状态中 `TravelingToSource` 每小时 `EnsureMovingTo(party, component.SourceSettlement)`；`ReturningHome` 每小时确认返回家乡。
3. `EnsureMovingTo` 若不是 `DefaultBehavior == GoToSettlement` 且 `TargetSettlement == destination` 则 `MoveToSettlement`；后者调用 `SetPartyAiAction.GetActionForVisitingSettlement()`。
4. 原版 `code/AiVisitSettlementBehavior.AiHourlyTick` 对无 `LeaderHero` 的部队可计算 `CalculateMergeScoreForLeaderlessParty`；征粮队没有领队英雄，可能受到影响。原版 `MobilePartyAi` 的 `DoNotMakeNewDecisions` 会参与即时主动行为筛选。
5. `ShouldPauseForThreat` 的原版规避状态或附近敌强判定成立时，维护6小时暂停重申路线的时间窗；仅 `HasSuperiorEnemy` 为 true 时函数本身**没有下达新的逃避移动指令**。是否由原版 AI 避敌需要实机验证。

**高可信假设**：原版自主访问定居点与 MOD 的定时目的地恢复互相抢目标，导致短时折返。**未证实**：一定是它、或一定每24小时由每日 Tick 触发。

## B. 第一阶段：零行为改变的路线日志（先部署）

记录征粮队每次实际变化时：

- `Party.StringId`、`HomeSettlement`、`SourceSettlement`、`MissionState`、`RequestedFood`、任务开始时间；
- 世界时间（CampaignTime，精确到小时）；
- `DefaultBehavior`、`TargetSettlement`、`ShortTermBehavior`、`ShortTermTargetParty`、当前位置、到目标距离（同一种量纲）；
- `IsNativeAvoidanceActive`、`HasSuperiorEnemy`、当前 `_threatAvoidanceUntil` 是否有效；
- MOD 控制器是否在该小时调用 `EnsureMovingTo`，若调用，旧目标/新目标和触发条件；
- 可选：最近24小时进展距离、累积折返次数、前一目标持续时间；避免每小时固定写全量 Info。

最小实现：在 `EnsureMovingTo` **只有调用 `MoveToSettlement` 前**输出 Debug 变更快照；在 `OnHourlyPartyTick` 检测现有目标与任务目标不一致且危机判断未触发时记录一次 Warn（同一队伍同一原因每日最多一次）。

为了精准归因：如样本仍不足，**仅对 `SupplyPartyComponent` 的部队**在原版 `AiVisitSettlementBehavior.AiHourlyTick`、相关 `SetPartyAiAction` 入口增加临时 Debug 日志，前后比较 `DefaultBehavior`/`TargetSettlement`；不修改其返回值。不要全局 Hook 所有 AI Party 并刷文件。

重点复现场景：无附近敌、50人征粮队从胡比亚出发前往恺拉，在游戏时间至少72小时持续观测；要求每次折返能定位到哪个行为先改了什么目标。

## C. 第二阶段：明确谁有路线控制权

### C1. 原则：只阻止无关的自主目标，保留即时避险

- **长期目标**：`SupplyPartyComponent` 的 `SourceSettlement`/`HomeSettlement` 等任务状态唯一决定。
- **战术短期行为**：原版遇敌、逃跑、绕敌、战斗接管优先；不通过每小时重新下命令打断。
- **状态转换**：购粮完成、粮源失效、返程、遇敌后恢复、失去家乡、读档后恢复时允许有一次明确定向动作。

### C2. 首选修复（验证日志指向原版自主访问后实施）

对 `AiVisitSettlementBehavior` 的普通自主拜访行为做专门过滤：只对 `party.PartyComponent is SupplyPartyComponent` 且拥有未完成任务的**征粮队**跳过该类评分；其他部队保持原版行为。实现形式可通过 Harmony Prefix 针对相应实例方法，注意该方法的 Harmony 签名、访问级别、具体类型必须在现项目 SDK 下编译验证；不得全局禁止访问定居点。

> 为什么不建议简单 `SetDoNotMakeNewDecisions(true)`：会影响原版 `MobilePartyAi.GetBehaviors` 对即时行为的决策，可能使输送队不能正常逃敌；若需要控制该布尔值，必须有验证数据说明即时避险仍有效，并提供反例测试。

若日志发现改目标来源不是 `AiVisitSettlementBehavior`，应针对**实际行为源**作同等范围限定，不要硬装上一个无效的 Patch。

### C3. `EnsureMovingTo` 与危险保护

现有检查只认默认目的地是否正确。推荐：

1. 当 `party.MapEvent != null`、队伍已停用或刚抵达，保持现有跳过。
2. 若 `IsNativeAvoidanceActive(party)` 或经过实测有效的威胁保护期中，不重新调用访问定居点命令；保留已有短期逃跑/绕路状态。
3. 若没有危险、任务目标确实被覆盖，才恢复一次任务目的地，并记录原/新目标。
4. 对连续多次改目标的队伍记录一次 Warn，但不每小时强制再改，防止循环。
5. `OnGameLoadFinished` 应重建恰当路线，但不得在原版正在战斗/逃跑时立即接管；核对读档后 `MissionState` 和当前目的地的对应。

### C4. 威胁模式风险

`TransportThreatModel.HasSuperiorEnemy` 只比较敌对关系、部队数量和周围半径；不要求敌人肉眼可见。对于 `HasSuperiorEnemy=true`、但 `IsNativeAvoidanceActive=false` 的情况，当前 `ShouldPauseForThreat` 返回 true **只是暂停目的地重申，并不保证有实际避险移动**。这是独立需要验证的安全漏洞候选。

若复现该情形：明确交给原版 AI 发避险命令的条件；如果原版不主动逃，选用经过 API 验证的安全躲避行为或安全等待点。不得让50人护卫面对优势敌人仍无指令直行。可改为在危险解除后才恢复原任务。

## D. 不允许的捷径

- 不设全局 `MobileParty.Ai.SetDoNotMakeNewDecisions(true)` 而不验证逃敌行为。
- 不每天或每小时无条件 `MoveToSettlement`；可能把已生效的逃跑短期行为挤掉。
- 不写死时间阈值为“每24小时必定触发”。观察是约24小时，代码驱动有小时、日更和原版 AI 多路径。
- 不删除 `ShouldPauseForThreat` 以制造表面直线行动。
- 不让对友方粮源的访问行为失效；只阻断原版自主无关访问，不阻断 MOD 明确的 `MoveToSettlement`。
- 不改所有 lord、caravan、villager AI；仅征粮队，在必要时扩展跨城援粮队，同样需各自测试。

## F. 验收场景

- [ ] **静态无敌人、路程大于72小时**：连续72小时目标不在家乡与粮源之间跳变；前往粮源的距离长期趋势下降。
- [ ] **每24小时复现**：变更前明确采集一次“原版改目标→MOD改回目标”或其它实际链路，变更后不再复现。
- [ ] **有优势敌军但未交战**：可以避开或躲避，不被任务每小时强制拉回危险路段；威胁消失继续目标。
- [ ] **敌军附近但没有触发 native 逃避**：判断是否需要 MOD 显式避险，不允许一直走向优势敌军。
- [ ] **来源失效或归属变化**：替换来源或安全返程，不来回横跳。
- [ ] **完成采购后的返回**：不会被原版自发改为前往其他城堡。
- [ ] **读档前后**：目标及短期危险状态不反复争抢，旧存档有效。
- [ ] **跨城援粮**：同组件 `IsAidMission=true` 路径不能被错误阻断和破坏。

## G. Worker 输出格式

提交两个可比较的日志片段：修复前一次折返的完整行为变迁、修复后至少72小时无危险行程；提交有敌人时 native 逃跑仍能触发的证据。任何不能确定的来源要明确写“未定位”，不能声称已证实某个原版行为。
