> 范围：`ModifiedArmy` AI兵力规划、驻军/封邑兵交换、职业兵生产与AI招募规则。无关外交等Mod不在本轮。

## 一、最终确定的设计原则

1. **唯一兵力目标**：保留现有 `PartyForceTargetModel` / `ForceManagementFacade.GetPartyTarget()`。和平时期目标为编制上限35%、最低50人；战争按Clan战争倾向；自有封邑防御采用专门目标。不得重写第二套兵力目标计算。
2. **唯一AI战略调度**：`AiForcePlanningBehavior` 每日决定补员、维持任务；未来可拓展战时休整。保留不同文化的封建兵/职业驻军兵/雇佣兵来源偏好、情境倍率，并联合评估“兵源+目的地”的可行性。
3. **统一定居点行动**：`PartyExchangeBehavior` 是受Mod管理的AI到访定居点后处理兵力操作的统一入口；`PartyExchangeModel` 审核已有兵员在 Mobile/Garrison/Fief 之间的流转；`PartyExchangeService` 调用底层组件实际执行。
4. **Model只决策，Service执行**：Model不得直接修改Roster、服役批次、库存、预算或下达行军命令。招募、转移、批次返乡的实效和日志由Service负责。
5. **取消AI招募构成比例模板**：删除 `aiRecruitmentTemplates.xml` 中的战斗兵种大类 min/max、Low/Middle/Top 等级 min/max 及依赖它们的评分/约束。其作用不应由另一套相似比例模板替代。
6. **职业兵按照具体兵种生产模板生成**：`professionalTroopTemplates.xml` 的文化、城镇类型、具体兵种及 `weight` 决定长期职业兵供给构成；兵营、文化、训练产能和Hearth等规则决定生产资格与总产量；招募Model只审核实际能否入伍。
7. **生产≠招募≠现有驻军比例**：生产份额要收敛到XML权重；现实驻军比例会受升级、伤亡、抽调、俘虏归顺与工资影响，不强行纠正既有驻军，也不按缺口无中生有地产兵。
8. **取消原版AI并行决策**：受Mod管理的AI自主驻军取兵、捐兵、旧招募与封建兵事务要走Mod统一审核；玩家操作、原版驻军初始化及明确范围外行为不得受误伤；特殊战后捐兵不得绕过Model。
9. **战时休整暂不开启**：当前方案不完整，继续保持 `WarRestPolicySettings.Enabled=false`；和平时期不进入WarRest。先不将休整当作本轮上线的必需功能。
10. **避免过度重构**：保留 `FiefPartyManager` 批次/Hearth/冷却事务、`TroopTransferService` 已经验证的安全转移能力、必要的俘虏归顺流程。只清除真正过时的独立策略和执行入口。

## 二、保留并复用的既有成果（不用重复造）

| 模块 | 已有/应保留的能力 | 验证事项 |
|---|---|---|
| `PartyForceTargetModel` | 和平固定比例、战争倾向、自有封邑防御目标 | 不改变目标结果 |
| `AiForcePlanningBehavior` / 相关Model | 每日战略评估、任务记录、目的地选择框架 | 处理任务取消与移动命令归属 |
| `PartyExchangeModel` / `PartyExchangeService` | 已实现四类流转的框架与部分事务复核 | 来源与接收方的双向安全、部分成功处理 |
| `FiefPartyManager` | 动员/服役批次、来源封邑、返乡冷却、Hearth记账 | 批次身份不能被普通兵转移破坏 |
| `GarrisonRecruitmentCapacity` | 驻军上限、软上限、征粮队回归人数预留 | 各来源补员均保留预留人数 |
| 文化军制与情境倍率 | Fief / Professional / Mercenary来源偏好 | 不被生产权重覆盖，两类权重用途不同 |
| `professionalTroopTemplates.xml` | 按文化/普通城镇/港口/城堡定义具体职业兵 | 作为**唯一职业兵种构成模板** |
| `basic_troop_config.xml` | 军种来源与兵营等级许可 | 保留职业兵资格规则 |

## 三、必做的新功能与修复

### A. 删除两套AI招募构成比例（高优先级）

- 删除/移除加载 `ModuleData/aiRecruitmentTemplates.xml`。
- 移除 `AIRecruitmentTemplate.cs`、`ArmyCompositionTemplate.cs`、`RecruitmentTemplateRepository.cs` 及其注册引用（先清点调用，再删）。
- 精简 `DefaultAiTroopRecruitmentModel`：去掉 `GetPriority()` 中以CombatRole和TroopQuality为目标的缺口/超额评分，不以任何 min/max 角色、Tier比例控制招募。保留人数目标、职业兵可用数量、工资、Clan预算、合法性、身份及事务审批。
- 精简 `RecruitmentSimulationState` 中只服务于旧比例评分的计数；若分类工具被其他真实用途引用，保留基础分类工具即可。
- `RecruitmentEvaluationResult` 中无用的 RoleShortage/QualityShortage 等诊断字段、旧 `RecruitmentLimitReason` 与对应日志文本，按调用关系清理。
- `GarrisonRecruitFromPrisonersBehavior` 的俘虏保留/出售策略仍依赖旧构成模板：必须先替换为**独立俘虏保留策略**，再删模板；保留合法性、归顺、经济与容量检查，不把职业兵生产模板误用于俘虏构成配额。
- 对领主Party抽取驻军兵力，不重新引入另一套硬性兵种/等级比例标准。

**验收**：全工程无残留的模板加载/依赖；同条件T3普通步兵与斧兵不会因为低阶比例需求而无限优先某兵种；原版/Mod俘虏逻辑不崩溃。

### B. 让职业兵生成真正服从 `professionalTroopTemplates.xml`（高优先级）

目标：在所有兵种都符合兵营、文化等生产条件且有足够产量的长期区间，兵种**生产数量**接近每个 `weight` 占比。

- 重写 `SettlementManpowerProductionBehavior.BuildDailyProfessionalOffers()`：不再对每一个生产名额选择 `EvaluateRecruitment().Priority` 最高的兵种，不能让当前驻军角色缺口、等级缺口覆盖模板权重。
- 生成时仅按**生产合法性**筛选：当前文化模板、定居点类别（城镇/港口/城堡）、兵营等级、兵种合法性。产能仍按已有文化军制、训练和Hearth资源计算。
- 采用**确定性、跨日累计的加权公平分配**（可选“按历史生产占比欠额最大者”或等价加权轮转），对每日只生产1~3人的情况也能长期收敛。不能每天独立四舍五入或始终固定从同一兵种开始。
- 分配账本按定居点及兵种持久化；模板兵种增删、兵营等级提升/降低、定居点易主、旧存档载入时做安全重建。避免数值溢出；`weight=0`的约定需明确（禁产或不允许配置），不要自动变1。
- 生产候选阶段只形成候选，不直接加入驻军或扣除购买费用。实际驻军招募继续由 `AiTroopRecruitmentModel` 的编制/工资/预算等审批与原有Hearth消费事务完成；不能把不可批准生产名额当成已经入伍。
- 预测接口和当日实际生产使用同一套无副作用分配计算，预测不能推进累计账本；只有真实生产完成才提交生产记录。
- 不为阿塞莱单独写条件：所有文化统一按各自模板执行。

**阿塞莱普通城镇示例**：模板权重为步兵3、弓箭手2、斧兵2、枪骑兵2。四兵种均满足资格时，长期生产比例应趋向 **3:2:2:2**。这是生产数量比，不是强制现有驻军保持该比例。港口城镇另有水兵权重；不应把模板外的骑射手凭空强制生产。是否增设骑射兵源属于独立文化设计议题。

**验收**：持续9/90/900名的分配误差可解释，低产量跨日收敛；三级兵营与文化一致时枪骑兵有合法生产机会；实际招募可能因工资/预算低于生产份额，但不得因旧比例评分偏斜。

### C. 统一AI调拨同时保护来源驻军（高优先级）

- `PartyExchangeModel.BuildRosterPlan()` 对“Garrison→Mobile”不仅检查总人数安全下限，还评估**来源驻军兵种多样性/稀缺度**，优先取走来源相对富余且接收方适用的士兵。
- 使用**软偏好**和边际得分，而不是新增严格的Infantry/Ranged/Cavalry或Tier配额；不能因无法精确匹配偏好而完全拒绝合理取兵。
- 已批准的一批士兵会改变双方名册、工资和剩余安全空间，计划及执行都要动态更新，不能在初始名册上排序后整批抽空某一兵种。
- 来源驻军必须保留现有防御下限、征粮队回归预留、关键身份保护。来源方不能因补员某一领主而出现骑兵/特定分支被全部抽空的长期系统性趋势。
- 普通兵从Mobile→Garrison同理审核Party自身留守安全、驻军接纳人数、工资与Clan财政。

**验收**：复现达努斯提卡抽兵和拉齐赫零骑兵案例；按名册差分验证士兵守恒、不透支驻军人数/工资，且不会制造新的软配额拒招问题。

### D. 修复统一入口与任务管理遗留问题（高优先级）

- 修复 `GarrisonCaptureSupplyBehavior.CanDonateTroopsAfterCapture()` 会消费一次性许可却被多个Harmony Prefix重复读取的问题；分为无副作用条件查询和一次性消费，并让**特殊战后捐兵也经过Mod的Model审批**。
- 受Mod管理的AI全部驻军取兵、捐兵及封建兵行动只有一个调度出口，不再由原版或旧Mod补丁在旁路直接修改名册。
- 修复 `AiForcePlanningBehavior` 任务取消/目标失效后，旧Mod `GoToSettlement` 移动命令未撤销的问题。只有确认命令仍归本Mod所有时才能接管或撤销，不能夺取战斗、军团和原版高优先级任务。
- 目的地评估使用游戏本体 `MapDistanceModel.GetDistance()` / 导航能力检查可达性和大致行程；使用已有避敌/紧急任务状态判断。**不另造寻路引擎**，原版负责移动过程。
- 重新核查 `PartyExchangeModel` 中可能有副作用的 `ReconcilePartyFiefTroops()`，放到Service的准备/执行阶段；重验实际库存、工资、Clan预算、驻军容纳额度；明确部分成功及回滚语义。
- 成功转移记录源/目标、兵种/数量/批次、审批与执行的差额；拒绝/异常只写日志，不在UI刷异常。

**验收**：同次定居点到达多次触发不会重复执行；取消补员后不继续奔向旧目的地；新征服城镇的原版特殊捐兵不再绕过Model，既不重复也不被误禁用。

### E. 删除确认废弃的兼容实现（在新入口稳定后做）

- 删除旧 `AiRecruitmentBehavior` 与同名旧任务路径，精简 `AiSettlementRecruitmentPatch` 到必要的Harmony拦截，完成 `PartyGarrisonExchangeBehavior` → `PartyExchangeBehavior` 的命名。
- 移除不再使用的 `IPartyGarrisonExchangeModel`、`DisabledPartyGarrisonExchangeModel`、Facade旧 `Exchanges`、`TroopTransferService.TryExecuteNaturalVisit()` 旧调度路径、过渡期 Disabled* 占位类。
- 清理 `Main.cs`、`SubModule.xml`、配置解析器和注册代码中的旧路径；存档数据要先确认兼容性，不能顺手删已持久化字段。
- `GarrisonRecruitFromPrisonersBehavior`、`RecruitPrisonersAiPatch` 不因名称“招募”而一刀切删除：其实际俘虏归顺业务仍然需要。
- 若保留旧配置开关用于回滚，应明确关闭时的降级行为和未来移除计划；不能让两套执行长期竞争。

**验收**：全工程引用检查、构建测试、存档加载、新建战役；玩家手动驻军/招募及商队等非托管Party不受影响。

## 四、暂不启用/本轮范围外

1. **战时休整**：现有 `WarRestPolicyModel` 初版尚未覆盖安全底线、普通兵转移、任务连续性。继续 `Enabled=false`；未来完善后单独设计、单独测试和放开开关。仅战争期间可以有主动WarRest，不把和平裁军混称WarRest。
2. **自动双向纯兵种换兵**：原配置默认关闭，不因为这次取消比例模板而自动启用。
3. **主动重编现存驻军**：不删除斧兵、不自动将老驻军强制重排为3:2:2:2；只影响未来的生产和合理交换。
4. **职业兵升级与平衡大改**：保留已有升级图谱与经验规则；除非实测发现单独Bug，不连带修改。
5. **俘虏招募并入PartyExchangeModel**：此前已决定俘虏归顺/费用/Conformity保留独立招募领域；仅共享编制、经济及合法性审核。
6. **所有文化强制具备骑射兵**：删除大类比例模板后，不存在“所有阿塞莱驻军必须有5%骑射”的约束；要新增骑射兵源，另行讨论历史文化设计。

## 六、重点回归测试

- **拉齐赫（3级兵营、定居点/Clan/王国文化相同）**：阿塞莱弓箭手、步兵、斧兵、枪骑兵都符合生产资格；记录每日生产候选、招募审批/执行、升级、驻军调出人数。检验生产权重3:2:2:2的长期收敛。若运行时Tier与XML `level`推断不一致，应以游戏中 `CharacterObject.Tier`为准，但取消比例模板之后Tier不再决定产出构成。
- **低产量**：每天仅1、2、3名，30～100天后权重收敛；旧存档导入可初始化累计状态；兵营从2升到3后枪骑兵开始进入合法生产集合。
- **支出不足**：职业兵候选仍依模板生成，实际招募按预算减少，Hearth/费用正确且不凭空生成或消耗士兵。
- **驻军抽兵**：保留驻军防御人数、征粮队预留；至少多种兵源可以被公平选择，不因为稀缺度偏好形成硬性拒招。
- **封建兵**：征召/返乡批次、来源封邑、服役期限、冷却、Hearth账本、存档保持一致。
- **任务与原版兼容**：军团、战斗、围城、紧急防御、战后攻城、玩家手动命令；停止任务不会保留幽灵移动目的地。
- **长期稳定性**：多个Clan、各文化、多个城市连续运行；核对人口来源和名册净变化日志，无重复调拨、无限生产、工资透支。

## 七、实际完成定义

1. 没有第二套等级/战斗大类配额强行影响职业兵生成或AI招募。
2. 职业兵生产长期遵守具体文化生产模板，且经过产能/资格和现实招募审批。
3. AI驻军/野战/封建兵之间的调拨全部由Mod统一批准和执行，来源与目标都受安全保护。
4. 受Mod管理的AI不再通过原版或过渡补丁旁路执行旧调兵。
5. 战时休整继续关闭，直到形成完整方案并单独验收。
6. 旧模板、旧入口与过渡类清理干净；不会造成旧存档、玩家操作和俘虏招募回归。
