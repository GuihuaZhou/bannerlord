# Bannerlord 和平、宣战决议与组合外交扩展实现分析

## 1. 文档目的

本文记录当前 `ModifiedPolitics` 对和平、宣战、战争倾向、战争潜力以及组合外交条款的实际接入情况，并解释下列游戏现象：

- 玩家主动寻求和平时，王国内所有 Clan 全部反对；
- 几分钟后敌国主动提出和平并愿意支付贡金；
- 敌国提案没有进入普通投票界面，而是提示贵族将决定权交给玩家；
- 同一场战争中，两种和平提案表现出完全不同的支持结果。

同时记录组合外交谈判新增的解除协议和加入战争条款，避免后续重复分析本体代码。

## 2. 当前和平与宣战是否考虑战争倾向

### 2.1 宣战决议

`DeclareWarDecisionPatch` 在本体 `DeclareWarDecision.DetermineSupport` 返回结果后，调用：

```text
WarDispositionDecisionSupport.Apply(...)
```

因此，普通宣战决议会在本体支持度基础上叠加各 Clan 的战争倾向：

- 战争倾向越高，越支持宣战；
- 战争倾向越低，越反对宣战；
- 修正方向会随“支持宣战”或“反对宣战”结果反转。

### 2.2 和平决议

`MakePeaceDecisionPatch` 同样在本体 `MakePeaceKingdomDecision.DetermineSupport` 返回后叠加战争倾向：

- 战争倾向越高，越支持继续战争；
- 战争倾向越低，越支持和平。

但是，补丁明确保留了两条本体强制分支。在命中这些分支时，不再叠加战争倾向。

### 2.3 战争倾向的修正方式

当前修正以本体支持分的绝对值为基数，最低修正基数为 `200`：

```text
修正基数 = max(abs(本体支持分), 200)
修正值 = 修正基数 × 战争倾向 / 100
```

支持战争的结果使用正向战争倾向；支持和平的结果使用反向战争倾向。

## 3. 当前和平与宣战是否考虑战争潜力

当前自定义 `WarPotentialModel` 没有直接进入本体和平或宣战决议的 `DetermineSupport`。

目前的实际情况是：

- 本体外交模型仍会考虑兵力、战争进展、风险、收益等本体因素；
- 自定义战争倾向会直接修正和平和宣战投票；
- 自定义战争潜力目前主要用于 UI 展示以及宗藩提案评分；
- 因此不能把“本体已经考虑实力”理解为“自定义战争潜力已经接入”。

如果后续需要让自定义战争潜力直接影响和平和宣战，应当单独设计修正幅度，避免与本体已有兵力、财政和战争进展评分重复计算。

## 4. 玩家主动求和为何会遭到全体反对

本体 `MakePeaceKingdomDecision.DetermineSupport` 存在一条强制分支：

```text
如果 IsPeaceSuitable(本国, 敌国) 为 false
并且提案不是敌国主动提出：
    支持和平 = 0
    支持继续战争 = 200
```

玩家从王国外交界面主动提出和平时，决议属于本国主动提案。

只要本体 `DiplomacyModel.IsPeaceSuitable` 判断当前不适合议和，所有 Clan 都会命中这条强制分支。此时：

- 所有 Clan 对和平返回 `0`；
- 所有 Clan 对继续战争返回 `200`；
- `MakePeaceDecisionPatch` 会识别这是本体强制分支；
- 战争倾向不会覆盖这项结果。

因此，“王国全部反对”并不一定代表每个 Clan 独立计算后都认为战争有利，而可能只是本体在提案入口处直接禁止了正常评分。

## 5. 敌国主动求和为何由玩家直接决定

敌国主动向玩家王国提出和平时，本体会创建带有以下状态的和平决议：

```text
isProposedByOpponent = true
```

如果玩家 Clan 是本国统治 Clan，本体又有另一条强制分支：

```text
如果评估 Clan 是玩家王国的统治 Clan
并且和平由敌国提出：
    接受和平 = 200
    拒绝和平 = 0
```

与此同时，`MakePeaceKingdomDecision.OnShowDecision()` 会为玩家创建和平提案地图通知，而不是直接显示普通的王国投票过程。

通知中会携带：

- 提案王国；
- 每日贡金；
- 贡金持续时间；
- 接受或拒绝操作。

这就是游戏显示“贵族们将决定权交到我手上”，并允许玩家直接确认的原因。

当前战争倾向补丁同样不会修改这条敌国主动提案的统治 Clan 强制分支。

## 6. 两种和平结果为何可以在几分钟内完全相反

两次操作走的是不同路径：

```text
玩家主动求和
  -> 本国提案
  -> IsPeaceSuitable 可能强制否决
  -> 全体 Clan 显示反对

敌国主动求和
  -> 敌国提案
  -> isProposedByOpponent = true
  -> 玩家统治 Clan 强制获得接受分数
  -> 地图右侧出现和平通知
  -> 玩家直接决定是否接受
```

所以这不是 Clan 在几分钟内突然改变意见，而是本体为“本国主动提案”和“敌国送来的提案”设计了不对称流程。

敌国愿意支付贡金还会进一步提升玩家接受提案的实际意愿，但地图通知的出现和统治者直接决定权本身来自本体和平决议逻辑。

## 7. 如何区分本体和平提案与 Mod 组合提案

### 7.1 本体和平提案

典型表现：

- 大地图右侧出现和平通知；
- 主要显示和平和贡金；
- 玩家可以直接接受或拒绝；
- 不一定进入组合提案的王国投票界面；
- 日志中没有 `[Kingdom negotiation]` 的组合提案记录。

### 7.2 Mod 组合外交提案

当前实现的表现：

- 王国决议标题带有“组合外交提案”标记；
- 投票说明列出完整条款；
- 金钱、领土、俘虏、条约和宗藩条件同时显示；
- AI 向玩家王国提交时，会进入玩家王国议会；
- 日志会记录组合提案的发起、评估、投票与执行。

## 8. 组合外交新增条款

当前组合外交数据结构新增以下条款类型：

- `EndTradeAgreement`：解除两国贸易协定；
- `EndAlliance`：解除两国同盟条约；
- `EndSubjectRelation`：解除附庸或傀儡关系；
- `JoinWar`：一方加入另一方针对第三国的战争。

这些类型追加在已有枚举末尾，避免改变旧条款的枚举数值。

## 9. 解除贸易协定

### 9.1 UI 条件

只有两国当前存在贸易协定时，谈判列表才显示“撕毁贸易协定”。

### 9.2 校验

提交和执行前都会确认贸易协定仍然存在。

同一提案不能同时包含：

- 建立贸易协定；
- 解除贸易协定。

### 9.3 执行

执行时复用本体：

```text
ITradeAgreementsCampaignBehavior.EndTradeAgreement(...)
```

执行后再次检查两国已经不存在贸易协定。

### 9.4 评分

当前解除贸易协定的基础评分采用建立贸易协定支持度的反向值。越支持继续贸易的 Clan，越反对撕毁协议。

## 10. 解除同盟条约

### 10.1 UI 条件

只有两国当前处于同盟状态时，谈判列表才显示“撕毁同盟条约”。

### 10.2 校验

同一提案不能同时包含：

- 建立同盟；
- 解除同盟。

如果提案要求一方加入战争，也不能同时解除双方同盟。

### 10.3 执行

执行时复用本体：

```text
IAllianceCampaignBehavior.EndAlliance(...)
```

执行后再次检查同盟关系已经解除。

### 10.4 评分

当前解除同盟的基础评分采用建立同盟支持度的反向值。

## 11. 解除附庸或傀儡协定

### 11.1 UI 条件

只有谈判双方之间实际存在宗主—附庸或宗主—傀儡关系时，才显示解除选项。

界面会根据实际关系显示：

- 撕毁与某王国的附庸协定；
- 撕毁与某王国的傀儡协定。

存在宗藩关系时，不再同时展示建立同盟、重新臣服等相互冲突的普通外交条款。

### 11.2 校验

提交和执行前确认两国之间仍存在对应的宗藩关系。

一份提案不能同时建立并解除宗藩关系。

### 11.3 执行

执行时复用统一入口：

```text
SubjectRelationAction.TryRelease(subject)
```

该入口负责移除宗藩数据、刷新贡赋，并输出宗藩关系解除日志。

### 11.4 评分

当前评分以主权恢复和宗主控制损失为基础：

- 附庸倾向支持恢复独立；
- 傀儡恢复独立的主权价值高于普通附庸；
- 宗主倾向反对失去附属国；
- 双方统治 Clan 的权重更高。

该评分后续仍可替换为现有解除附庸、宣布独立决议的完整本体式支持计算。

## 12. 加入第三国战争

### 12.1 条款含义

`JoinWar` 明确记录：

- 哪个谈判王国负责参战；
- 要加入的是针对哪个第三国的战争。

例如：

```text
北帝国加入东帝国对西帝国的战争
```

其中北帝国是条款提供方，西帝国是条款目标对象。

### 12.2 UI 条件

当一方正在与第三国交战，而另一方尚未与该第三国交战时，未参战一方的外交列表会显示“加入对某王国的战争”。

### 12.3 同盟要求

加入战争复用本体召战协议，因此要求：

- 两个谈判王国已经结盟；或
- 同一组合提案中先建立同盟，再执行加入战争。

不能在同一份提案中既解除同盟又要求加入战争。

### 12.4 评分

参战评分复用本体 `AllianceModel`：

- 参战方使用 `GetScoreOfJoiningWar`；
- 请求方使用 `GetScoreOfCallingToWar`。

因此会继承本体对敌我实力、召战成本和战争价值的判断，而不是简单给予固定分数。

### 12.5 执行

执行时复用：

```text
IAllianceCampaignBehavior.StartCallToWarAgreement(...)
```

组合提案中的显式金钱条款负责外交补偿，因此当前召战协议本身传入的额外召战付款为 `0`。

执行顺序保证：

```text
建立同盟
  -> 加入战争
  -> 处理后续解除条款、俘虏、领土和金钱
```

执行后确认参战方确实已经与第三国进入战争状态。

## 13. 存档与恢复

为了支持 `JoinWar`，正式条款记录新增了第三国 `Kingdom` 引用。该字段使用新的可保存属性编号，不修改旧字段编号。

以下流程都会保存新增条款：

- 等待王国投票的组合提案；
- 已批准但尚未全部执行的提案；
- 玩家否决后保留的反提案草案。

执行器继续使用逐条完成位置和幂等状态检查，防止加载存档后重复建立或解除协议。

## 14. 当前限制与后续建议

### 14.1 战争潜力尚未接入普通和平与宣战

如果需要接入，应先分析本体外交分数中已经包含的实力与财政因素，再只加入自定义战争潜力提供的增量信息，防止重复放大。

### 14.2 本体和平强制分支仍然保留

当前没有覆盖 `IsPeaceSuitable` 导致的全体强制反对，也没有覆盖敌国求和时玩家统治 Clan 的强制接受分数。这是有意保留本体流程，而不是遗漏。

如果后续决定修改，应当分别处理：

- 是否允许玩家在本体认为“不适合和平”时仍然发起正常投票；
- 敌国提案是否仍由玩家直接裁决；
- 战争倾向是否应该影响这两条强制分支。

### 14.3 解除宗藩关系的评分仍可深化

目前使用独立的主权与控制价值评分。后续可以复用现有宗藩解除和独立决议的逐 Clan 评分，使和平解除、单方面独立和组合谈判解除保持完全一致。

### 14.4 新增条款需要游戏内测试

建议分别验证：

1. 解除贸易后协议状态和贸易收入消失；
2. 解除同盟后双方不再被视为盟国；
3. 解除附庸和傀儡后贡赋与战争义务停止；
4. 已有同盟下要求加入战争；
5. 同一提案中先结盟再加入战争；
6. 投票过程中第三国灭亡、战争结束或协议提前失效时，提案被安全拒绝；
7. 保存并加载包含 `JoinWar` 的待投票或待执行提案。
