## M6 阶段补充对账

- 设计要求“收养与联姻为不同事务”：已落实为独立 `Adoption/AI`、`Adoption/Models`、`Adoption/Execution`。
- 设计要求同伴先清除 `CompanionOf` 再设置 Clan：已按此顺序实现并进行结果校验。
- 设计要求跨 Clan 贵族不得直接写入 Clan：已在写入前处理总督、军团、领主部队及跨王国敌对状态。
- 设计要求不得覆盖亲生父母：执行过程只写入 `AdoptiveKinshipRecord`，未修改 `Father` 或 `Mother`。
- 设计要求临时状态不直接废弃：战斗、被俘、逃亡返回临时阻碍，并在 30 天执行窗口内按日重试。
- 设计要求真实运行测试：当前仅通过编译，因尚无 M7 玩家入口，收养执行仍需在游戏中验证后才能标记完全验收。
- 额外完成 MCM 汉化：模组名称、日志分组、字段、提示及日志级别均提供简体中文文本；设置仍按索引持久化，切换语言不会改变日志阈值。

## M7.1 阶段补充对账

- 设计要求没有通知 UI 时不得开启 AI→玩家：M7.1 同时启用地图通知和 `EnableAiToPlayer`，未提前开放不可见请求。
- 设计要求请求可恢复：提议继续由 Behavior 持久化；每条提议增加 `PlayerNotified`，未通知的旧记录在会话启动时补发，通知本身注册为 Saveable 类型。
- 设计要求玩家可接受、拒绝和反提议：通知检查窗口提供三种操作；已有反提议的谈判链不再显示第二次反提议。
- 设计要求反提议可改变归属与礼金：界面提供两种婚后归属，并分别支持零礼金、玩家支付5,000、要求对方支付5,000第纳尔。
- 设计要求玩家从家族成员和其他 Clan 发起：尚未实现，明确留在 M7.2，因而本阶段不标记完整 M7 完成。
- 设计要求复用相同 Service API：所有 UI 操作均调用 `FamilyProposalService`，通知层不直接修改持久化状态。

## M7.2 阶段补充对账

- 设计要求玩家从家族成员安排联姻：Clan 页面增加“家族事务”入口，可选择除主角外的合资格家族成员；主角个人婚姻继续使用原版求爱路线。
- 设计要求浏览其他 Clan：界面按合法家族和合资格人物分两级选择，不绕过 Marriage Model。

- 设计要求同伴入口收养：可从玩家家族同伴名单选择被收养人，再选择法定收养人，成功后进入已批准待执行状态。

## M7.2 实机问题修正对账

- 实机未显示入口的原因不是 XML 未部署，而是地图通知注册补丁的 Harmony 实例参数名称错误；补丁异常发生后，原初始化顺序跳过了 UIExtender 启用。
- UIExtender 初始化现与 Harmony 兼容补丁隔离。某个版本相关补丁失败时，玩家入口仍可加载并将原因写入日志，符合 M7“正式界面可用”的要求。
- 首次实机验证表明，海战 DLC 的 `NavalGauntletClanScreen` 在加载横向三按钮容器时发生原生崩溃；为保证兼容性，Clan 页面恢复为单个轻量“家族事务”入口，其二级菜单继续分别提供联姻、两类收养及可恢复收件箱。后台仍复用同一 Service API，没有绕过 Model。
- 地图通知补丁改用 Harmony 规定的 `__instance` 参数，恢复 AI→玩家通知类型注册。该项仍需下一次实机启动确认按钮布局、点击命令和通知点击链路。

- 独立 Movie 根控件已移除阻断子控件输入的属性，恢复“继续”和“关闭”按钮事件；仍需实机验证滚动、重复打开和关闭后的焦点恢复。

## M7.4 人物页操作简化与文化规则迁移

- 人物页已经确定操作对象，因此删除联姻和收养的前置确认 Movie：点击“联姻”直接选择目标家族，点击同伴的“收养”直接以主角为法定收养人创建内部收养，不再重复选择当前人物。
- 按钮名称由“安排联姻”“办理收养”缩短为“联姻”“收养”。
- 目标家族和目标人物列表改为调用 `FamilyProposalService.CanCreateMarriageProposal`，该接口复用正式创建时的 Model、人物锁和冷却检查，UI 不再只检查基础 Clan 合法性。
- 根据本次明确需求，文化口径从 `Hero.Culture` 迁移为 `Clan.Culture`；资格校验、AI 候选分档和价值评分同步迁移。异国同家族文化仍允许，异国异家族文化禁止，同国异文化仍由集中开关控制。
- 联姻目标选择不再使用通用多选弹窗，改为参考本体 `KingdomManagement/Clan` 与 `ModifiedPolitics/KingdomClan/UI` 的独立页面：左侧为带旗帜的合法家族列表，右侧显示所选家族名称、大旗帜及可联姻 Hero 头像网格，右下方提供关闭和选择对象按钮。列表数据仍由 `CanCreateMarriageProposal` 生成。
- 上述复杂联姻页面首次实机布局不合格，现暂停接入。按用户要求退回最小 UI 验证阶段：人物页“联姻”仅打开参考百科弹层结构的空白独立页面，保留遮罩、画布、标题和关闭按钮；Clan/Hero 数据待基础弹层多次开关验收后再加入。
- 最小页面首次实机出现白色背景，原因是自定义遮罩使用了普通 `Color` 属性，与本体百科的 Brush 渲染方式不同。现已直接复用本体 `EncyclopediaBar.xml` 的 `Encyclopedia.SoundBrush` 遮罩、`Encyclopedia.Frame` 主框、`StdAssets\\tabbar_popup` 标题框及 `Popup.CloseButton`，仅将标题和关闭命令绑定到 ModifiedFamily ViewModel。
- 设计要求收件箱可恢复：Clan 页面提供收件箱入口，即使地图通知被关闭或丢失，仍可重新打开所有有效入站请求。
- UI 只调用 Service：创建、接受、拒绝、反提议均通过 `FamilyProposalService`；ViewModel 和通知不直接修改存档集合。
