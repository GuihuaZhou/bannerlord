# S8 实机验收执行手册

本手册只用于收集 `T01_T24_ResultMatrix.md` 的真实运行证据。短时启动和
普通游玩属于冒烟测试，不能代替指定场景。所有测试均使用存档副本；一旦
发现兵员、金币、粮食、牲畜或户数无法解释地变化，立即停止保存并保留日志。

## 每次测试前

记录以下信息：

- 当前 Commit、游戏版本、ModifiedArmy/ModifiedPolitics 是否启用；
- 测试人、存档 ID、战役日期以及测试开始/结束时间；
- 涉及队伍与定居点的兵员、伤员、俘虏、金币、粮食、牲畜和户数快照；
- 本次只执行的 T 编号，避免一次运行混合多个不可区分的事务。

证据至少包含对应时间段的 `ModifiedArmy.log`。资源守恒类测试还应保存
操作前后截图或抄录数值；读档测试必须记录保存点和重新载入后的时间点。

## 建议批次

### A：启动、依赖与 Patch（T14、T23、T24）

1. 同一 Commit 分别在启用和禁用 ModifiedPolitics 时启动新战役或存档。
2. 保存两份启动日志，确认 ModifiedArmy 均可进入战役且无程序集加载错误。
3. 核对 `ForceEntryPatchAudit` 输出；目标方法应只有预期 owner 和单次拦截。
4. 触发一次佣兵市场刷新和一次工资计算，记录调用结果，确认没有原版与
   Mod 双执行。仅启动成功只能支持 T23 的加载部分，不能直接通过 T24。

### B：事务与恢复（T01–T06、T21、T22）

按正常提交、部分提交、陈旧快照、可回滚异常、不可回滚异常分别使用独立
存档副本。每次记录源/目标名册前后值和 OperationId。T06 必须保存冻结现场，
退出后重新载入，确认任务仍冻结且不会自动重试；不得在生产存档制造异常。

### C：封邑、兵源与驻军（T07、T15、T17）

至少跨一个每日 Tick，对比封邑户数、服役批次、职业兵 offer、驻军容量、
实际新增兵员和费用。预测界面打开前后不得改变任一资源。俘虏招募、销售和
解散合并分别记录金币及名册变化。

### D：征粮与运输（T08–T12）

分别准备粮仓充足、粮仓不足、沿途有敌情和运输在途四份副本。T10 记录至少
72 个战役小时的目标变化；T12 在运输途中保存并重新载入，继续记录送达和
返程，核对 Cargo、护卫和目标定居点。

### E：生命周期与长期运行（T13、T18–T20）

同一游戏进程依次载入 A、B、A，记录任务 ID 和活动队伍；新游戏记录奖励前后
金币及装备；旧版与新版存档各完成一次载入；最后用新游戏快进 30 天并保留
完整错误日志。长期运行无报错不能反向替代前述故障注入测试。

## 结果填写规则

- `PASS`：场景完整执行，填写具体证据位置、测试人和精确 Commit。
- `FAIL`：可复现地违反不变量，记录最小复现步骤并停止发布。
- `BLOCKED`：缺少存档、注入条件或可观察数据；说明缺少什么。
- `WAIVED`：只允许 T21–T24，并在证据栏写明批准人和具体理由。

填写后运行：

```powershell
./ModifiedArmy/tools/Test-RuntimeAcceptanceEvidence.ps1
```

准备作发布决定时再运行 `-RequireGo`。退出码 2 表示证据完整但尚未达到 GO，
不是脚本故障。

全部批次完成后可使用统一入口：

```powershell
./ModifiedArmy/tools/Invoke-ReleaseValidation.ps1 -RequireGo
```
