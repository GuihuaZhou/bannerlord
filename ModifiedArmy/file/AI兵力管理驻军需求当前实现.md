# AI兵力管理：驻军防御与外援需求当前实现

本文记录当前代码已经实现的行为，不修改或替代原设计文档。

## 一、当前实现范围

本阶段已经实现：

1. 判断定居点属于边境还是非边境。
2. 计算驻军最低保留人数。
3. 预测未来七天的本地驻军补员。
4. 计算是否需要外援以及请求的士兵人数。
5. 计算来源驻军最多可以安全调出多少正规士兵。
6. 向文件日志输出玩家王国相关定居点的判断结果，并对重复状态去重。

本阶段尚未实现：

1. 尚未创建并派遣实际的跨城增援部队。
2. 增援路线模型仍是保守Stub，不会自动启动运输任务。
3. `EnableAutomaticReinforcement`仍为`false`。
4. 尚未实现兵种价值、兵种构成和多来源驻军之间的调拨优化。
5. 尚未把模拟驻军粮食天数作为外援触发条件。

## 二、驻军最低保留人数

最低保留人数只计算正规驻军，不计算民兵。

```text
边境最低驻军 = 向上取整（驻军硬上限 × 90%）
非边境最低驻军 = 向上取整（驻军硬上限 × 50%）
```

不根据附近敌军数量、附近敌军总兵力或围城状态增加额外需求。

示例：驻军硬上限为300人时：

- 边境最低保留270名正规驻军。
- 非边境最低保留150名正规驻军。

这里的最低保留人数是防守判断和外援判断的基准，不是自动生成新兵的上限。

## 三、外援需求

边境和非边境定居点都可以产生跨城增援需求，没有紧急、常规等优先级。

```text
预计驻军 = 当前正规驻军 + 未来七天预计本地补员
请求人数 = 最大值（0，最低保留人数 - 预计驻军）
```

判断结果分为：

- 当前正规驻军已达到最低线：不请求外援。
- 当前驻军不足，但预计七天内可以依靠本地补员达到最低线：暂不请求外援。
- 预计七天后仍低于最低线：请求恰好补足剩余缺口的人数。

示例：边境驻军上限300人，当前240人，七天预计补充10人：

```text
最低保留人数为270人
预计驻军为250人
请求外援20人
```

## 四、安全调出人数

“安全调出人数”表示来源驻军在不跌破自身最低保留线的情况下，最多可以调出的正规士兵人数。

```text
安全调出人数 = 最大值（0，当前正规驻军 - 最低保留人数）
```

示例：

- 边境驻军上限300人、当前285人，最低保留270人，最多安全调出15人。
- 非边境驻军上限300人、当前200人，最低保留150人，最多安全调出50人。

该结果只是人数方面的最大值。实际跨城调兵接入后，还需要继续受目标容量、运输Party容量、财政、兵种价值和路线安全检查约束。

## 五、80%、90%和驻军最低线的区别

三个比例服务于不同环节：

| 比例 | 用途 | 上限300人的结果 |
|---|---|---:|
| 80% | 自动生成职业兵、招募俘虏的停止线 | 240人 |
| 90% | 普通现有士兵转移到目标驻军时的容量线 | 270人 |
| 边境90% | 边境驻军最低保留线和外援判断基准 | 270人 |
| 非边境50% | 非边境驻军最低保留线和外援判断基准 | 150人 |

普通现有士兵转移上限为90%，含义是普通捐兵、Party与驻军之间转移已有士兵时，目标驻军通常最多接收到硬上限的90%。这不会删除已经超过90%的驻军。征粮队等已预留编制的士兵返还仍可以到达100%的硬上限。

## 六、配置

配置位于`ModifiedArmy/ModifiedArmy/ModuleData/militaryConfig.xml`的`ForceManagement`节点：

```xml
<InteriorDefenseRatio value="0.50"/>
<BorderDefenseRatio value="0.90"/>
<ReinforcementForecastDays value="7"/>
```

缺少这些节点时，代码使用相同的默认值。

## 七、日志

驻军判断日志使用Notice等级写入文件，只记录玩家王国的城镇和城堡。

为避免每日重复刷屏，同一定居点只有在以下关键信息变化时才重新记录：

- 是否请求外援发生变化。
- 判断原因发生变化。
- 最低驻军人数发生变化。
- 边境或非边境状态发生变化。

日志使用口语化中文，包含当前正规驻军、最低驻军、未来七天预计补员、请求人数以及不请求或请求的原因。
