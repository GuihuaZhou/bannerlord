# 兵源生产与职业兵文化判定

## 当前机制

旧版“职业兵池/封建兵池”库存已经删除。系统不再把士兵长期存入独立兵池：

- 职业兵按日形成可用生产名额，并在招募时直接补充到目标部队；
- 封建兵按日形成分配名额，并直接补充到封建部队；
- 存档只保留小数生产进度与周期统计，不保存职业兵或封建兵库存；
- 旧存档键 `_settlementRecruitmentPools` 保留不变，仅用于兼容已有存档。

## 职业兵文化规则

职业兵生产实时读取：

```text
S = Settlement.Culture
C = Settlement.OwnerClan.Culture
K = Settlement.OwnerClan.Kingdom.Culture
L = 实际 BarracksLevel
```

遇到定居点文化、有效 Owner Clan、有效 Kingdom 或相应文化缺失时，当日不生产职业兵，不回退到原版兵种。

| Settlement / Clan / Kingdom | 模板文化 | 生产倍率 | 开放兵营等级 |
|---|---|---:|---:|
| A/A/A | A | `1.00` | 1–3 级 |
| A/A/B | A | `1.00` | 1–2 级 |
| A/B/A | A | `0.50` | 1–2 级 |
| A/B/B | A | `0.50` | 仅 1 级 |
| A/B/C | A | `0.25` | 仅 1 级 |

有效兵营等级为：

```text
effectiveBarracksLevel = min(actualBarracksLevel, culturalMaximumLevel)
```

职业兵每日基础产量为：

```text
MilitaryDoctrine.Training.base + MilitaryDoctrine.Training.barracksStep × effectiveBarracksLevel
```

最终生产进度再乘文化倍率。小数进度写入定居点生产数据，达到整数时形成当日可招募名额。

## 模板与兵种分配

模板 ID：

```text
{cultureId}_castle
{cultureId}_town
{cultureId}_town_port
```

港口城镇没有专用模板时回退到同文化 `town` 模板；没有任何匹配模板时不生产。

每个兵种配置权重与所需兵营等级。系统根据累计生产历史选择相对目标权重缺口最大的兵种，使长期产出接近 XML 配置比例，而不是维护一个有容量上限的库存池。

## AI 驻军调拨

旧 AI “Volunteer”路径已经改名并收敛为 `GarrisonTransfer`：

- 只从允许调拨的城镇或城堡驻军中取兵；
- 统一经过当前人数、工资和驻军保护规则；
- 不再把驻军调拨描述为志愿兵招募；
- 村庄不作为驻军调拨目标。

## 封建兵生产

封建兵模板仍按定居点文化解析，但不再保存封建兵库存，也不再使用旧版每周最小/最大补充公式。每日生产结果通过封建兵分配流程直接补入封建部队，界面显示当前每日预计分配量。
