# 兵源池与职业兵文化判定

## 1. 代码位置

| 文件 | 职责 |
|---|---|
| `ModifiedArmy/Recruitment/Pools/Behaviors/SettlementRecruitmentPoolBehavior.cs` | 兵池存取、每日生成、职业兵文化关系判定、兵营上限和速率倍率 |
| `ModifiedArmy/Recruitment/Pools/Models/SettlementRecruitmentPoolData.cs` | 定居点职业兵与封邑兵库存、生成进度的存档数据 |
| `ModifiedArmy/Recruitment/Pools/Models/RecruitmentPoolTemplateRepository.cs` | 按文化和定居点类型解析职业兵/封邑兵模板 |
| `ModifiedArmy/Recruitment/Pools/Models/RecruitmentPoolTemplate.cs` | 模板接口、兵种权重、兵营等级和生产公式 |
| `ModifiedArmy/Recruitment/Pools/Models/ProfessionalTroopTemplate.cs` | XML 职业兵模板反序列化与兵种配置解析 |
| `ModifiedArmy/Recruitment/Pools/UI/PlayerRecruitmentPoolPatch.cs` | 将职业兵池呈现在玩家招募界面并执行库存交易 |

## 2. 两套兵源

每个城镇或城堡分别保存：

- `ProfessionalTroops`：职业兵池；
- `FiefTroops`：封邑兵池；
- `ProfessionalProductionProgress`：职业兵小数生成进度；
- `FiefProductionProgress`：封邑兵小数生成进度。

两套库存互相独立。

### 2.1 封邑兵

封邑兵模板始终按照 `Settlement.Culture` 解析。Owner Clan 或 Kingdom 的文化变化不会改变封邑兵文化。

### 2.2 职业兵

职业兵在每次生成时即时读取：

```text
S = Settlement.Culture
C = Settlement.OwnerClan.Culture
K = Settlement.OwnerClan.Kingdom.Culture
L = 实际 BarracksLevel
```

系统不保存历史统治状态，也不保存同化度或军事整合度。

## 3. 无效统治状态

遇到以下任一情况时，当日不生成职业兵，职业兵容量查询和生产量均返回 0：

- Settlement Culture 为空；
- Owner Clan 为空；
- Owner Clan 已灭亡；
- Owner Clan Culture 为空；
- Kingdom 为空；
- Kingdom 已灭亡；
- Kingdom Culture 为空。

当前实现不会在 Clan 无 Kingdom 时使用 `K = C` 回退。这是后续明确覆盖原始设计文档的边界规则。

封邑兵不受这些职业兵条件影响。

## 4. 文化组合规则

A 表示定居点文化，B、C 表示与 A 不同的文化。

| Settlement / Clan / Kingdom | 职业兵模板文化 | 生成倍率 | 开放兵营等级 |
|---|---|---:|---:|
| A/A/A | A | 高速 `1.00` | 1–3 级 |
| A/A/B | A | 高速 `1.00` | 1–2 级 |
| A/B/A | A | 中速 `0.50` | 1–2 级 |
| A/B/B | A | 中速 `0.50` | 仅 1 级 |
| A/B/C | A | 低速 `0.25` | 仅 1 级 |

### 4.1 A/A/A

三者同文化。使用定居点 A 文化职业兵模板，完整开放实际兵营的 1–3 级兵种。

### 4.2 A/A/B

定居点与直接统治 Clan 同文化，Kingdom 为异文化。仍使用 A 文化模板和高速生成，但最多开放 2 级。

### 4.3 A/B/A

定居点与 Kingdom 同文化，直接统治 Clan 为异文化。使用 A 文化模板，中速生成，最多开放 2 级。

### 4.4 A/B/B

Clan 与 Kingdom 同为异文化 B，但不能替换当地职业兵体系。继续使用定居点 A 文化模板，中速生成，仅开放 1 级。

### 4.5 A/B/C

定居点、Clan、Kingdom 分属三种文化。继续使用定居点 A 文化模板，低速生成，仅开放 1 级。

## 5. 兵营等级

实际兵营等级读取范围被限制到 0–3。文化关系不会修改建筑本身，只计算本次生产使用的有效等级：

```text
effectiveBarracksLevel = min(actualBarracksLevel, culturalMaximumLevel)
```

例如实际兵营为 3 级，但文化组合是 A/B/B，则本次只允许模板中 `RequiredBarracksLevel <= 1` 的兵种参与生成。文化关系恢复后，高等级建筑无需重建即可重新开放。

## 6. 生成速率

模板的原始每日产量为：

```text
baseDailyProduction + dailyProductionStep × effectiveBarracksLevel
```

结果再乘文化关系倍率：

```text
实际每日职业兵进度 = 模板每日产量 × 文化倍率
```

当前倍率：

- 高速：`1.00`；
- 中速：`0.50`；
- 低速：`0.25`。

小数进度保存在定居点兵池数据中。累计达到整数后才生成士兵。

## 7. 模板解析

模板 ID 由目标文化和定居点类型组成：

```text
{cultureId}_castle
{cultureId}_town
{cultureId}_town_port
```

港口城镇找不到专用 `town_port` 模板时，会回退到同文化的 `town` 模板。找不到任何对应模板时，当日不生成该兵池士兵。

封邑兵解析继续使用 Settlement Culture；职业兵解析使用第 4 节判定出的文化。当前五种有效组合最终都使用 Settlement Culture，但仍保留按指定文化解析模板的仓库接口。

## 8. 兵种资格与分配

模板中的每个兵种包含：

- 兵种对象；
- 权重；
- 所需兵营等级。

只有所需兵营等级不高于本次有效兵营等级的兵种可以生成。

系统不是随机抽取，而是选择“距离权重目标数量缺口最大”的兵种：

```text
target = poolCapacity × troopWeight / totalEligibleWeight
shortage = target - currentTroopCount
```

每生成一人就重新选择最大缺口，从而长期趋近模板权重比例，并避免随机连续偏向同一兵种。

## 9. 容量

兵池容量由当前解析出的模板决定，不随兵营等级增加。

当前库存总数达到模板容量后停止生成。职业兵文化变化时，旧文化库存仍占用同一个职业兵池容量，因此需要先被招募或消耗，新的 A 文化职业兵才可能继续补充。

## 10. 已有士兵和文化变化

文化关系变化只影响之后的每日生成。已经存在的士兵：

- 不删除；
- 不转换文化；
- 不降级；
- 不因开放兵营等级下降而移除；
- 继续占用兵池容量，直到被招募或消耗。

已有小数生成进度也会保留，并在新的实时文化规则下继续累积。

## 11. 玩家和 AI 消耗

读取兵池时返回库存快照，调用方不能直接修改存档字典。真实消耗必须通过 `TryConsume`，且只有库存足够时才会原子扣除指定数量；库存不足不会进行部分扣除。

玩家职业兵界面和 AI 职业兵招募均从同一个定居点职业兵池扣除库存。

## 12. 当前规则摘要

```text
封邑兵文化 = Settlement Culture

职业兵：
  无有效 Owner Clan / Kingdom -> 不生成
  有效统治关系 -> 五种组合均生成 Settlement Culture 职业兵
  文化关系只改变生成速度和开放兵营等级
```

其中 A/B/B 与 A/B/C 的最终规则是：

```text
A/B/B -> A 文化，中速，仅 1 级兵营
A/B/C -> A 文化，低速，仅 1 级兵营
```
