# 雇佣兵酒馆生成机制

## 1. 配置与代码位置

| 文件 | 职责 |
|---|---|
| `ModifiedArmy/ModuleData/mercenaryTemplates.xml` | 按定居点文化配置刷新概率，并按具体兵种配置权重和生成数量范围 |
| `ModifiedArmy/Mercenary/Models/MercenaryTemplate.cs` | 读取 XML、校验兵种条目并执行加权选择 |
| `ModifiedArmy/Mercenary/Patches/MercenaryMarketPatch.cs` | 替换原版酒馆雇佣兵刷新，应用选中兵种自己的数量范围 |

## 2. 配置层级

文化模板只负责：

- `culture`：使用该市场的定居点文化；
- `spawnChance`：该文化酒馆刷新成功的概率；
- `MercenaryTroops`：该文化允许出现的兵种池。

每个 `troop` 节点独立负责：

- `id`：兵种对象引用；
- `weight`：在当前文化兵种池中的相对抽取权重；
- `minCount`：该兵种一次生成的最少人数；
- `maxCount`：该兵种一次生成的最多人数。

示例：

```xml
<troop id="NPCCharacter.hire_knight"
       weight="8"
       minCount="5"
       maxCount="10"/>
```

## 3. 刷新流程

1. 根据城镇文化查找模板；
2. 如果酒馆已有普通雇佣兵且不是强制刷新，则不刷新；
3. 按文化模板的 `spawnChance` 判定本次是否生成；
4. 按兵种 `weight` 加权选择一个 XML 指定兵种；
5. 使用该兵种自己的 `minCount/maxCount` 随机生成数量；
6. 将酒馆雇佣兵替换为选中的兵种和数量。

不存在有效兵种条目时不会回退到原版普通雇佣兵。兵种引用无效、权重非正数、最小数量非正数或最大数量小于最小数量的条目会被忽略。

## 4. 当前迁移原则

本次从文化级数量范围迁移到兵种级时，为避免同时改变既有平衡，先把原文化范围复制给该文化下的每个兵种。以后可以直接修改单个 `troop` 的 `minCount/maxCount`，无需改代码，也不会影响同文化的其他雇佣兵。
